## 第一章 项目要解决的问题

系统面对的是一组持续产生多通道读数的设备。它要同时做三件事：第一，发现单个读数或短时段的异常（点异常与上下文异常）；第二，发现"正常"本身在变化（概念漂移），并把漂移与异常区分开；第三，在漂移发生后让检测器继续有效（适应），同时不让适应本身制造新的误报。全部工作在无标签条件下进行，运行在流式计算框架上，每台设备的处理相互独立（随设备数线性扩展），并且要可复现——同样的输入两次运行必须给出相同的输出。

理论设计文档以电网相量测量单元的数据流为目标写成；工程实现在一个室内物联网数据集上完成了机制的验证。理论文档的场景目录把这类数据定位为概念漂移场景（S7）的类比数据，用来预先验证适应闭环的机制；电网数据上的验证列为后续工作。

## 第二章 工作方式：两条线与它们之间的纪律

项目由两条线组成。理论线维护理论设计文档，它是规格，只由用户修改。工程线按模块分阶段实现，每个阶段以一份交接文档开工，以一份收口记录结束，阶段中间的所有决定用裁决书固定；工程线的发现以"理论回传"的形式带回理论线，由理论线决定是否修订规格。两条线之间的接口是开发设计日志（`dev_design_log_zh.md`），它记录全部约定、决策、数据事实、开放问题与回传事项，按版本号累加。

工程线内部由三个角色构成：用户（裁决、提交代码与设计文档、在本地运行数据提取）、开发设计会话（起草交接文档与裁决书、维护日志、不写代码）、代码开发 agent（实现、测试、运行实验、写报告；遇到与交接文档或理论矛盾之处只报告、不绕过）。仓库的 `docs/design/` 只由用户提交，`docs/handover/` 存放交接文档与裁决书原文，`docs/reports/` 存放代码开发 agent 的报告，`docs/<模块>/` 存放实验产物。

有几条纪律贯穿始终，新来的人最先要知道的就是它们。

**逐位等值。** 任何结构性改动都以"改动前后输出逐位相同"证明无害；在线算子与离线参考实现、Java 与 Python、同一配置的两次运行，都必须逐位或逐条相同。唯一的容差例外是跨语言的超越函数（对数、指数），允许 1e-12。等值的范围是事件时间上产生的全部输出，按处理时间产生的诊断量（训练缓冲占用、按墙钟采样的快照）不在范围内。逐位相同只在同一主机、同一 JDK 上成立，跨主机只要求离散决策量相同。方法细节见《逐位等值方法手册》。

**离线先行，在线只做等值。** 每个检测器或决策函数先有一个离线参考实现（通常是 Python），在历史转储上跑完全部实验、定好参数与判读口径，再把同一函数搬进在线算子；在线阶段只证明"在线等于离线"，不再调参。

**确认性运行约定。** 集群上的运行只在结果决定一项裁决时才做，一次只改变一个量；全量重放约十小时，一律设置有限的重启次数（三次），重放完整性八条断言全部成立才算一次有效运行。

**不迎合约定。** 结果与预期不符时，先按"代码、理论（交接文档）、数据出处、数据本身"的次序排查；排查到数据本身的，登记为数据事实，不修改算法、门槛或参数去迎合预期。判读口径与预期在运行前写定并随提交入库。

**语言约定。** 所有文档用完整的中文句子，不用电报式缩略语，借用的术语首次出现时定义。

## 第三章 理论架构的要点

理论设计文档把系统分为八个模块，以规格卡描述每个模块的职责、接口、变体点、平台落位与关联。本章只列与实现直接相关的部分。

**数据接入与标准化（M1）**：摄入、按设备分组、窗口化、鲁棒标准化（中位数与四分位距），维护原始缓存供重训与状态重建；标准化统计量是零级适应的对象。

**点异常检测（M2）**：滑动窗内的距离式离群判定，实现为微簇离群检测算法 pMCOD；半径与邻居数为部署期校准参数，漂移适应靠重估标准化参数而不是改半径。输出离群标志与内部监测信号（离群率等）。

**上下文异常检测（M3）**：每台设备一个浅层长短期记忆自编码器，只在正常数据上训练，用重构误差经分布校准得到标准分；误差流送性能层监测。变体点开放（重模型与相关矩阵特征为候选），本项目用主选的浅模型。

**漂移监测（M5）**：三个子模块。数据层（M5a）在原始特征上做逐日分布检验捕批内突变与长记忆变化；性能层（M5b）用最优窗口漂移检测器 OPTWIN 监测重构误差流捕缓变退化；差分层（M5c）利用邻近设备残差做全局与局部归因，本项目未实现。

**适应执行（M6）**：按漂移类型分三级响应——零级只重估标准化统计量，一级快速重训上下文模型，二级收敛驱动的重训；治理重训数据质量（训练集异常剔除）与更新执行的正确性（状态重建协议）。

**聚合与告警（M7）**：跨设备聚合，执行报警与响应决策矩阵的融合判决，输出带全局或局部归因的告警。

理论的报警与响应决策矩阵以"哪一层报了"为维度：只有数据层为突变漂移走一级；只有性能层为缓变退化、零级先行、不回落则二级；两层同报为已伤及性能的漂移走一级；离群率爆发与数据层同现判为分布切换、点通道静默。工程线在它上面加了"范围"（全局或局部）与"时间形态"（瞬态或持续）两维，并因后来的实测把"零级先行"一行改写（见第六章与第十章）。

理论文档还给出了验证计划（十项）、风险清单、场景目录与平台落位，本项目直接涉及的是：第二项验证（最优窗口检测器默认参数的鲁棒性）、第四项（三层融合矩阵的消融）、第五项（数据层统计方案对比，推迟）、以及第十二条决策（上下文通道选型）相关的离线网格。

## 第四章 数据集与我们查明的事实

数据集是 SYNERGIA 室内物联网数据：八台设备（伪标识 A 至 H）装在同一实验室的不同位置，每十秒一轮，每轮五个检测通道（温度、湿度、气压、气体、光照）与三个质量侧信道（气体置信度、信号强度、加速度计）。全集覆盖 2022 年 2 月 11 日至 7 月 25 日；本项目的比较期是 3 月 1 日至 4 月 30 日，其中 3 月 1 日至 8 日是标定周。探索性分析用 Python 在用户的本地机器上流式完成。

数据事实清单（日志第四节）有四十三条，这里按对设计的影响分组列出最重要的。

**格式与完整性。** 气压单位是帕而不是说明文件写的百帕；光照在六万五千五百三十六处饱和，按右删失处理；有一段一周的数据是另一周平移十四天的近似拷贝，按非数据处理；3 月 30 日原始数据有约一小时的全场缺口，之后的离群率爆发是窗口排空的产物；Kafka 按消息自带的时间戳判过期，重放历史数据必须把保留策略设为永久。

**标定窗口的代表性。** G 的光照在 2 月 25 日至 3 月 6 日处于连续人工照明之下，标定周的光照尺度只有正常的五十分之一（数据事实第三十四条）；气体、气压、湿度的七天标定尺度在全队上一致偏离整月尺度，说明存在周期长于一周的天气尺度变化（第二十七条）；固定的标定窗口不可能代表一个缓慢变化的世界，运行期尺度重估是结构性必需。

**事件与节律。** 3 月 22 日至 27 日是全场环境事件：气体中位数抬高一到一点七个标定宽度、日内宽度扩大二点五到六倍、湿度同期下降（第三十条）。气体自 3 月 14 日起相对标定周整体抬高且此后未回到标定周水平（第三十六条）。4 月有五个全场气体抬升时段，持续八到十九小时后回落，集中在凌晨与傍晚（第三十五、三十八条）。C 的正午日照直射与 D 的午后温度是局部的周期性现场因素。气压相对标定周的偏离是八台同日的天气现象，约一半的可评价日偏离（第四十三条）。

**检测器对变化速率的响应（第三十一条）。** 点通道对突变即时可见、对平滑变化失明；上下文通道对两倍宽度以上的阶跃全程报警、对爬坡有时延地检出、对一倍宽度边缘；传感器卡死对两个通道按构造不可见，由质量守卫承担。

**适应机制的行为（第三十九至四十二条）。** 一天的重估窗口把天气通道的尺度收窄五到十二倍而制造偏离；上下文模型绑定于训练时的标准化坐标，零级重估会直接破坏它（超阈率升到八成）；重估窗口跨过变化点时新参照落在新旧工况之间；一级重训的训练窗口取变化点之前时无论多长都差一个数量级，取之后三天即回到初始模型的量级。这四条是本项目对"表示层适应"这一设想最重要的修正。

## 第五章 工程实现的架构

![系统全景](figs/system_overview.png)

**运行环境。** Java 11，Flink 1.13.6，Kafka 2.6.3，深度学习库 DL4J 1.0.0-M2.1，统计分布用 Apache Commons Math；三节点集群（主节点承载作业管理器与第一个 Kafka 代理，两台工作节点各一个 Kafka 代理与四个槽位的任务管理器）。重放器保留 2022 年的原始时间戳作为事件时间，按倍速发送，只在全场无数据时压缩空闲；全部模块的定时器都是事件时间定时器；水位线延迟五十五秒。检查点三十秒。源主题八个分区、一台设备一个。

**数据接入（M1）。** 成轮器把同一时间戳的读数拼成一轮，三十秒后关闭，不完整的轮带缺失掩码下发（任何可解析读数的时间戳都成一轮，包括只有质量通道的）。质量守卫统计每通道连续相同读数的游程，超过设备级阈值即打标（传感器卡死）。标准化在标定窗口结束后冻结：中位数与四分位距，光照先做对数变换；预热期间检测静默。冻结时生成参照直方图（四百零一条等质量边加两个溢出箱）与参数集，附在第一条标准化轮上下发。紧凑原始缓存保留七天（每轮五个双精度读数、时间戳、三组掩码）。参数版本号从一起计，每次零级加一，随轮下发；每个版本的第一条轮附该版本的参数集。

**点异常检测（M2）。** pMCOD 核心，一小时窗、一分钟滑动步，邻居数十，逐设备半径（D 为 0.75、G 为 1.5，其余 1.0，离线网格定值）；判定与"到达滑动步"对齐，输出离群记录与十分钟离群率。带掩码的轮旁路。版本变化时清空该台状态，用随轮附带的回填附件重建一个窗长，回填的点不发判定。

**上下文异常检测（M3）。** 每台一个自编码器：编码器与解码器各一层、隐单元六十、窗长六十轮、批六十四、学习率 0.001、耐心二十、上限三百轮；数据段为七天训练、两天早停、七天标定（不重叠窗口），训练集剔除含点通道离群轮的窗口，G 的光照输入置零。主分是分布校准的标准分，阈值 2.22（三倍标准差折算成四分位距单位），每十分钟一个评分。训练在算子内的执行器上异步进行（补遗四）：不可变快照、结果槽、有界受检查点保护的缓冲、排空期间输出水位线保持，使训练的墙钟时间不影响事件时间上的输出；相同输入下训练逐位可复现。上下文模块保存训练完成时的参数集，从原始值自己按训练版本标准化（"上下文通道不跟随零级"），只在一级或二级切换时换版本；评分记录带训练版本与模型代数。

**性能层漂移监测（M5b）。** OPTWIN 按论文公式实现（置信度 0.99、鲁棒度 0.5、最小窗三十、最大窗两千零一十六、单侧、F 检验在前），输入为上下文主分流；加六小时持续性核对（候选之后六个元素的中位数高于参照加鲁棒度倍历史标准差，持续三十六个元素）才确认，否则撤销。模型代数改变时清空该台检测器。

**数据层漂移监测（M5a）。** 以冻结参照直方图为基准，每个当地日对五个通道做 KS 与 G 检验（显著性 0.01 经五通道校正），加按通道推导的效应量门槛（温度 0.38、湿度 0.73、气压 0.84、气体 0.43、光照 0.51），事件语义为状态转移（进入偏离、回落）；逐日位置与尺度统计量（偏移倍数、宽度倍数）；十分钟离群率送入同一个 OPTWIN 实现，其确认作为"爆发"（分布切换的变化点标记）。质量门槛：缺轮或守卫打标超过两成的设备日不可判。零级生效后换用新参照、状态清零、不发回落事件，日记录带版本号；湿度与气压的参照不随零级变化。

**聚合与决策（M7，并行度一）。** 输入为上述全部事件流与质量信号。小时节拍（当地整点后六十秒）：逐台计算点通道标志（离群率超过 0.0613）、上下文标志（六窗中至少三窗超阈）、性能层标志（已确认未回落）、数据层标志（之前两个日界之一偏离，只看同版本）、爆发标志（已发出且报警元素在前两小时内）；在场设备数乘四分之三向上取整（至少两台）为共模门槛；按"质量问题、分布切换、漂移、现场条件、瞬态事件、异常"的次序归因；告警写入告警主题。日节拍（当地日界后六十秒）：按"连续两日偏离、当日偏离且性能层已确认、性能层确认跨日界"三条规则判持续，查决策矩阵，发命令（生效时刻为下一日界，命令序号按设备计），同一段偏离只发一次，冷却期一天；日界复核补标当日不可判与分布切换。现场条件以最近七天同钟点至少三次有标志且温度、气体、光照任一通道的变换域小时均值相对同钟点基线偏离超过参照宽度的一半来判。升级格：只有性能层持续为一级，一级后七天内性能层新确认段为二级，两层同报为一级，只有数据层持续为零级，零级后七天内同通道新持续段为一级；各级冷却只阻止同级。

**适应执行（M6）。** 命令经命令主题回到数据接入模块的标准化算子（命令源发最大水位线），存入受检查点保护的状态，在事件时间到达生效时刻时执行；生效时刻须为滑动步整数倍；水位线迟到、已处理轮迟到、冻结前命令三类都计数，断言为零。零级：用缓存中生效前七天的轮（剔除守卫打标的）重估中位数与四分位距，湿度与气压换回冻结参数，版本号换为命令序号加一，同一窗口重新生成参照直方图，把生效前一小时的轮按新参数标准化作为回填附件，两者附在第一条新版本轮上。一级与二级：数据接入模块不重估，只把命令随轮转发给上下文模块；一级为生效后三天的入口轮按当前版本标准化、冷启动重训，旧模型服务到提交那一轮，新模型从缓冲头评分，原子切换；二级回到收集态按首次训练的数据段重训，期间静默并标记。一级切换前的"新模型不优于旧模型则不切换"做成参数、默认关闭（待确认）。

**主题与记录。** 源主题、评分主题、监测主题、漂移主题 `synergia-drift`、告警主题 `synergia-alerts`、命令主题 `synergia-adapt`。版本号与模型代数在各记录上为可空字段，命令回路关闭时为空且不写进 JSON，所以关闭时的输出与引入命令回路之前逐字节相同。

## 第六章 时间、确定性与命令的语义

系统的确定性建立在三件事上。第一，一切按事件时间：轮、窗口、节拍、命令生效都用事件时间定时器，处理时间只产生诊断量。第二，命令锚定在生效事件时间上：聚合模块在决定时刻（日界）之后一个确定的边界（下一日界）生效，命令经 Kafka 回到上游的到达时刻是非确定的，但只要它在事件时间上先于生效时刻到达（迟到计数为零），两次运行就逐位相同；第三，训练移出任务线程，训练的快慢只改变墙钟上的延迟，不改变事件时间上的输出（输出水位线在排空期间保持）。

与命令有关的四个时间参数都是可调的：告警节拍（默认一小时，下限十分钟）、决策节拍（默认一天）、等待时长（默认一个日界，是"长瞬态与永久漂移不可区分"问题的显式权衡，缩短则被长瞬态骗到的次数增加）、生效提前量（默认一天，下限由迟到命令为零决定，真实部署分钟级即可）。从偏离进入到零级生效的典型延迟为四十八小时。

重放完整性八条断言：逐日轮数对账、无重复、时间戳覆盖时段边界、冻结时刻在预期位置、重启次数为零、迟到丢弃为零、两个检测通道覆盖到时段末尾、迟到命令为零。

## 第七章 实验体系

**片段矩阵。** 没有真值标签，评价的办法是把登记的数据事实当作标注段：三月事件、气体抬高、四月五个时段、C 正午、傍晚气体、G 光照、十四段注入（尖峰、阶跃、爬坡、卡死）、平稳日、天气通道；每段在运行前写定每个检测器与决策层应当看到什么，运行后并排实测。预期分开环与闭环两档。

**开环与闭环。** 聚合模块收口时的离线实验是开环的；链式离线实验把决策函数、八台设备的模拟器（调用在线同一组函数）与数据层重算串起来逐日推进，是开发机上二十秒可跑完的离线闭环，用来选定零级参数并检验闭环预期；全量重放是真正的在线闭环。链式实验的三档重估窗口（一天、七天、只重估位置）与"湿度气压不重估"开关给出了零级默认值的依据。

**消融与扫描。** 三层融合的消融（只用数据层、只用性能层、只用检测通道、全部），共模比例（二分之一、四分之三、全体），时间参数的十二种组合，上下文门槛，现场条件天数；全部配置下 Java 与 Python 逐条相同。

**重训实验（开放问题第十二条）。** E 在 3 月 28 日一级重训：训练窗口位置（生效前或后）、长度（三、七、十四天）、热或冷启动，五个种子，三项度量（耗时、平稳段超阈率、注入召回）；两档补跑分离了"零级留下的尺度"与"训练窗口位置"两个成因。

**验收。** 每个阶段的验收项固定为：单元测试与跨实现等值；离线实验报告（判读口径逐条填写）；短重放等值（八天到十天、一百二十倍速）；时延表与性能表；收口记录。

## 第九章 仓库结构与怎样动手

- `docs/design/`：理论设计文档、开发设计日志、逐位等值方法手册、实验设计说明、示意图（`figs/`）。用户提交。
- `docs/handover/`：各阶段交接文档（`handover_*_zh.md`）、裁决书（`ruling_*_zh.md`）、收口记录（`*_closeout_zh.md`）。原文照录。
- `docs/reports/`：代码开发 agent 的开工核对、口径、实验报告、实现说明、验收报告。
- `docs/m2/ m3_a4/ m5a/ m5b/ m7/ m6a/ m6b/`：各阶段的离线产物、转储、核对表；大文件不入库，报告给出再生成命令。
- `eda/`：本地数据提取脚本（成轮与解析规则与在线一致）；`m7/ m6a/ m6b/`：离线参考实现、离线运行器、链式驱动、报告生成与核对脚本；`deploy/scripts/`：集群编排（`syn-` 前缀）、手工命令工具、复位与断言脚本。
- Java 源码按模块包组织：`m1`（成轮、守卫、标准化与自适应标准化算子、紧凑缓存）、`m2`（pMCOD）、`m3`（自编码器、训练执行器、算子）、`m5a`、`m5b`、`m6`（命令、零级纯函数、模拟器、链式驱动）、`m7`（决策函数、输入装配、离线运行器）。

一个新开发者动手前的顺序：先跑单元测试；再用 `m7/decide.py` 与 Java 离线运行器复现聚合模块的开环基线并比较（应逐字节相同）；再跑链式驱动的四档（约二十秒一档）并与报告表格核对；需要上集群时先读确认性运行约定与复位脚本的门槛，短重放（一百二十倍速、约两小时）之前先在开发机上把离线对照准备好。每份报告末尾都有"复现方式"一节，写明环境、命令、前置条件、期望产出与常见失败。

## 第十章 已固定的结论、已知的偏离与开放的问题

**已固定的开发决策**（日志第三节，十二条）：深度学习库在上下文阶段引入并促成 Java 11 迁移；实现顺序；室内数据集为首期主数据集；通道二分；探索性分析先行；重放器的时间语义；数据接入的预决策；复用旧集群；工程仓库；卡死由守卫承担；"决定"归聚合、"执行"归适应执行；湿度与气压不随零级重估。

**对理论的偏离与回传**（日志第六节，二十九条）。最重要的一组是关于零级与一级协议的：上下文通道不跟随零级（第二十七条，已采纳，全量重放影子评分再验证）；零级的重估窗口不能一刀切、天气通道不应随零级重估（第二十六条，已作为开发默认）；重估与重训的窗口应锚定在变化点之后（第二十九条，一级已按此选定，零级待实现）；决策矩阵"零级先行、不回落则二级"一行失去前半段（第二十八条）。其他已登记的还有：最优窗口检测器的作者代码与论文的偏离（第十八条）；长记忆检验的有状态语义与平稳日定义（第二十三条）；气压与湿度作为天气通道的处理（第二十一条）；离群率爆发是变化点标记（第二十二条）；长瞬态与永久漂移的不可区分与等待时长参数（第二十四条）；现场条件需要范围维度（第二十五条）。

**技术债与已知弱点。** 数据接入模块拿不到点通道离群标志，零级只剔守卫轮；冻结与重估的取样规则不同；聚合模块为无状态设计却保留了小状态；现场条件规则分不清周期现场因素与按日程重复的异常；告警只有一个主标签；一级切换缺"重训后验证"（参数已做、默认关闭）。

**开放问题。** 零级窗口锚定在变化点的实现与验证；"连续反向命令"作为升级信号；跨级冷却是否需要；二级重训期间的监测预案；电网数据上的验证；差分层与跨视图一致性。
