## 二、当前的重点

当前的重点是把闭环跑通并验证：让聚合模块的命令真正改变上游的参数与模型，再看这样的系统在整个两个月的数据上是否比不适应更好、好在哪里、坏在哪里。具体就是适应执行第二批剩下的四步：零级默认值变更（湿度与气压不随零级重估）后的链式实验补跑，决策矩阵升级格，一级与二级的短重放，以及一次一百五十倍速的全量重放（带影子评分，用来再验证"上下文通道不跟随零级"的裁定）。全量重放是整个工程线的第一次完整闭环在线运行。

与之并行的另一个重点在理论线：工程线已经积累了二十九条理论回传意见和四十二条数据事实候选，其中关于零级与一级协议的几条（第二十六、二十七、二十八、二十九条）已经形成一个连贯的修订意见，需要理论文档做出裁决，工程线才能把相应的开关定为正式默认。

## 三、已经解决的问题，以及这套架构在本数据集上能做到什么

### 三点一：解决的问题

按时间顺序，工程线解决的问题可以分为四类。

第一类是让系统本身正确而可复现。这包括 Java 11 迁移、检查点与通信帧的容量、窗口时间戳口径、点通道判定与滑动步的对齐、上下文模型的架构修正与批量扫描中的损失坍缩、冷启动阻塞、异步训练的水位线保持与有界缓冲、Kryo 序列化器找不到用户类导致的无限重启；最终结果是全量运行在相同输入下三次逐位相同，上下文模型的训练也逐位可复现。这是后面所有实验能被信任的基础。

第二类是把理论规格落成可执行的定义。例如 OPTWIN 按论文而不是按作者代码实现、持续性核对的加入；数据层的等质量分箱、按通道的效应量门槛、状态转移语义、爆发的时序；聚合模块的两档节拍、共模门槛、六类归因及其优先次序、时间形态门控；零级的重估、重冻、回填与命令的事件时间锚定。每一处都经过了开工核对、离线口径确认、离线实验、在线等值四步。

第三类是查明数据集本身的性质。四十二条数据事实候选中最重要的几条：G 的标定窗口被连续人工照明污染（光照尺度只有正常的五十分之一）；气体自三月十四日起相对标定周整体抬高、此后没有回到标定周水平；三月二十二日至二十七日的全场事件；四月五个全场气体抬升时段集中在凌晨与傍晚、有日内周期；C 的正午日照直射与 D 的午后温度是局部的周期性现场因素；三月三十日原始数据有约一小时的全场缺口；湿度与气压是天气驱动的、时间尺度以周计的通道。这些事实决定了每个检测器"应当"看到什么，也是论文里解释结果的依据。

第四类是发现并刻画了适应机制的真实行为。开环实验证明不执行命令的系统会让多数设备长期停留在"漂移"状态；闭环（链式离线）证明零级确实解除了这种覆盖；同时发现了三个此前理论没有写明的问题——重估窗口的长度（一天对天气通道不具代表性）、重估窗口的位置（跨过变化点的窗口让参照落在新旧工况之间，事件中继续偏离、事件后平稳日反成偏离）、以及重估参数与模型的耦合（上下文模型绑定于训练时的标准化坐标，零级重估会直接破坏它，一级重训又会继承零级留下的尺度）。

### 三点二：这套架构在本数据集上的检测能力

下面按"能做到什么"与"效果如何"分层说，数字都来自已收口的报告。

点通道（pMCOD）能在一小时窗内识别相对邻居孤立的轮，平稳日的小时离群率中位数为零、第九十九百分位约百分之六；注入的尖峰只持续十到三十秒，落不到小时离群率门槛上，所以点通道在聚合层面对尖峰不可见，但在逐轮判定上可见。

上下文通道（LSTM 自编码器）在 E 的六段注入（三段尖峰、三段阶跃，幅度为冻结尺度的 2.85 到 11.4 倍）上，初始模型检出四段（阶跃全部、尖峰一段），四月五日的其余一百零一个窗口零误报；平稳段的窗口超阈率约百分之七（阈值设计值约千分之一点三，差距来自误差分布的非正态性与标定周与之后工况的差别）。它对 C 正午日照、傍晚气体上升这类真实的工况变化也会报警，这些按"不迎合"约定被登记为数据事实，并在聚合层面由归因处理而不是在检测器上压掉。

性能层（OPTWIN）在平稳日上五十个设备日只有一次确认，三月事件尾部八台中七台确认，十四段注入零确认——它区分了"模型性能持续退化"与"短暂异常"。它的弱点是单侧（只报误差上升）和没有确认的结束事件，后者由聚合模块定义的回落补上。

数据层（逐日 KS 与 G 检验）能看到检测器看不到的长记忆变化：气体自三月十四日起的抬高、G 光照的标定污染、三月事件在每个通道上的进入与回落，并给出逐日的位置与尺度统计量。它的局限是日分辨率（最快一天后才知道）和对冻结参照的依赖——参照一旦被污染或过时，它报告的是相对那个参照的偏离。

聚合与决策在开环下把两层监测与两个检测通道融合为六类归因与零级命令；闭环（链式离线）下的效果是：漂移小时由六千零六十八降到一千三百五十五，三月事件八台都收到命令，G 光照一条命令后保持正常到四月下旬，E 不再长期处于漂移期而注入小时可以被看见，命令总数六十条，从偏离进入到命令生效的典型延迟四十八小时（一天等待加一天提前量）。代价是基线污染：七天窗口下命令后反向偏离再命令的实例二十九例，其中十一例在七天内。

一级重训在离线实验上的结论是：训练窗口取变化点之后三天、冷启动、天气通道参数冻结时，重训模型在之后平稳段的超阈率回到初始模型的量级（约百分之七到九）；若窗口取变化点之前，无论多长都差一个数量级。召回因零级留下的温度尺度被拉宽而由四段降到两到三段。

一句话概括：**这套架构在本数据集上已经能够在无标签条件下持续运行两个月，区分短暂异常、全场环境事件、局部周期因素与真正的分布漂移，对漂移做出可逆的参数级响应并使监测层恢复灵敏；它尚未证明的是模型级响应（一级与二级）在线闭环的效果，以及全量重放下整个闭环的稳定性。**

## 四、潜在问题与困难，以及解法

**第一，零级与一级的协议需要理论线修订，工程线在等。** 四条相互关联的回传意见：上下文通道不跟随零级（第二十七条，已采纳，待全量重放影子评分验证）；零级留下的尺度会传给一级、天气通道不应随零级重估（第二十六条，已作为开发默认，待理论裁决）；重估与重训的窗口应锚定在变化点之后（第二十九条，一级已按此选定默认，零级尚未实现）；决策矩阵"零级先行、不回落则二级"一行失去前半段（第二十八条）。解法是理论线一次性裁决这一组，工程线把第二十九条在零级上做成窗口起点参数并在链式实验上验证，这应是第三批的第一项。

**第二，基线污染是闭环的固有代价，目前只有事后计数，没有事前防护。** 等待一个日界再决定、七天窗口、同一段只发一次、冷却期，这些都在减少它，但链式实验仍有十一例七天内的来回。解法有两个方向：第二十九条的窗口锚定（从源头减少混合参照），以及把"命令后反向偏离"本身作为一个信号——连续两条反向命令时不再重估而是升级为人工审计或一级。后者是决策矩阵的一格，第三批可加。

**第三，评价没有真值标签，只有注入段与数据事实。** 当前的办法是片段矩阵：把登记的数据事实当作标注段，预先写定每段的预期，再并排实测；加上消融（单层对组合）、敏感性扫描（共模比例、时间参数、门槛）与开环闭环对照。对论文而言这是诚实的，但审稿人会问"效果"的单一数字。解法是在论文里把注入段的召回与误报、平稳日的命令数、漂移覆盖小时数、命令后恢复天数作为主指标，并说明为什么无标签场景下不能有更强的指标。

**第四，理论文档面向 PMU 电网数据写成，实验在室内物联网数据上做，两者之间的映射要在论文里讲清。** 场景目录（S1 至 S7）里本数据集覆盖的是 S7（概念漂移）与部分 S2、S4、S6 类比；差分层、跨视图一致性、FDIA 判别都没有做。解法是把本数据集定位为"适应闭环机制的预验证"（理论文档本来就为负荷域类比数据留了这个位置），PMU 数据的验证列为后续工作。

**第五，工程上的脆弱点。** 全量重放约十小时，集群曾因无限重启被拖垮；上下文模型训练在开发机上一次数分钟到一小时，五个种子乘多档的实验要半天；八台的轮表与注入都依赖用户在 Mac 上的提取。解法已经在约定里：有限重启、确认性运行、离线先行、提取脚本的成轮与解析规则与在线对齐。还有两项技术债：数据接入模块拿不到点通道离群标志，零级只剔守卫轮；冻结与重估的取样规则不同。

**第六，几条规则已知有弱点，暂不修。** 现场条件规则分不清周期性现场因素与按日程重复的异常（注入爬坡被归为现场条件）；它对气体引起的标志是用气体佐证气体；聚合模块为无状态设计却保留了小状态；聚合的告警只有一个主标签，异常信号在漂移期要从载荷里查。这些都登记在理论回传第二十五条与待办里，等理论线决定是否改规则。
