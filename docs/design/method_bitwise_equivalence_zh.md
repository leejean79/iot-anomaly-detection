# 验证方法手册：逐位等值比较
# Method Manual: Bitwise Equivalence Comparison

> 地位：开发线的方法手册，与开发设计日志并列存放在 `docs/design/`，只由用户提交。它把一种在本项目里反复使用的验收手段写成可执行的规程，供设计会话、代码开发 agent 与论文写作共用。
> 来源：第二阶段的等值验收（2026 年 9 月 18 日约定）、三月重跑确立的"输入相同则逐位相同"（10 月 2 日）、补遗四的核心验收项 A4-2（10 月 13 日）与步骤 C 的强杀恢复验证（10 月 15 日）。

## 第一节：它是什么

一次运行会产出一组数字：每台设备训练时每一轮的损失、早停轮数、阈值校准得到的中位数与四分位距、阈值本身，以及在线阶段每一个窗口的评分。逐位等值比较，是把两次运行产出的这些数字一个对一个地对齐，要求每一个数字完全相同，精确到浮点数的最后一位；有一处不同即判为不同。它不是"相差不超过百分之一"，也不是"统计上无显著差异"，而是精确相等。

```
 基准运行                                 待验证运行
 设备 E 的评分文件                        设备 E 的评分文件
 窗口 1   0.734215618                     窗口 1   0.734215618   相同
 窗口 2   0.701883042                     窗口 2   0.701883042   相同
   …                                        …
 窗口 N   1.102344901                     窗口 N   1.102344902   不同 ← 最后一位不同即不同
```

## 第二节：它为什么成立

计算机的计算是确定性的。只要满足下列前提，两次运行每一步浮点运算都得到相同结果，最终数字必然逐位相同：

1. 输入数据相同，且进入计算的顺序相同；
2. 随机数种子相同（决定网络权重初始值与任何随机采样）；
3. 数学库以单线程运行（多线程归约会改变浮点加法的顺序，浮点加法不满足结合律）；
4. 同一套代码、同一个运行时版本、同一类硬件。

本项目的实测依据：三月重跑（10 月 2 日）确立"输入相同则逐位相同"；补遗四步骤 C（10 月 15 日）在训练中强杀任务管理器、作业恢复两次之后，八台设备的训练结果与全部评分窗仍与未打断运行逐位相同。

## 第三节：什么时候用精确等值，什么时候用容差

判据取决于两次计算"按构造应该多像"：

| 情形 | 判据 | 本项目的实例 |
| --- | --- | --- |
| 同一套代码、同一份数据、同一个种子，只改变运行位置、数据流动的管道或恢复路径 | **逐位相同** | 补遗四（训练移出任务线程）；强杀恢复；两段重放与单段重放 |
| 两套不同实现在算同一种数学（运算顺序不同、近似方法不同） | 容差（本项目用正负百分之一） | 离线探针与在线点异常通道的窗口统计 |
| 输入本来就不同（注入与不注入、不同的数据段） | 不比较数值，比较行为 | 召回表、误报率 |

原则：凡是"本意是一个数字都不改"的改动，一律用逐位相同验收；用容差验收这类改动是把真正的缺陷放过去。

## 第四节：为什么它比容差判据有力

管道类改动（线程、缓冲、排空、水位线、检查点恢复、代理键、重放分段）按设计不应影响任何计算结果。如果某个窗口的评分在小数点后第九位不一样了，一定是管道改变了数据：掉了一轮、重复了一轮、顺序乱了、窗口拼错了、训练看到的数据不一样了。这类缺陷造成的数值差异往往极小，容差判据看不见它们。本项目的教训：第二阶段的时间戳缺陷使点通道的窗口点数少了一半，它躲过了四道验收，正是因为没有一道验收拿同一个统计量做精确比较（开发设计日志数据事实第二十八条）。

一次逐位比较同时检验了多件事。以步骤 C 的强杀恢复为例，"恢复后逐位相同"一句话同时证明：重新提交训练用的是与原来完全一样的那些窗口；缓冲里的轮一轮没丢；恢复后的排空顺序没有乱。换成近似比较，这三件事要分别设计检查。

## 第五节：规程

1. **确定基准运行。** 基准必须是已通过重放完整性七条断言的有效运行，并且其产物（训练日志、阈值、评分文件）已落盘存档。
2. **锁定前提。** 待验证运行与基准运行必须：同一份输入数据与同一注入方案；同一随机种子；数学库单线程（`OMP_NUM_THREADS=1`，训练线程内同样如此）；同一提交的代码，只允许本次要验证的改动；运行时版本相同。任何一项不同，先登记再运行，并在报告中注明。
3. **对齐。** 逐设备对齐训练产物（训练轮数、每轮损失、早停集误差、标定中位数、四分位距、阈值）与评分文件（按设备与窗口终点时间戳对齐）。两边窗口数必须相等；不等本身就是不同，先报窗口数差异再报数值。
4. **比较。** 以打印出的数值文本逐行比较（本项目主分打印到小数点后九位）；或以二进制表示比较。两种都可，报告中写明用的是哪一种。
5. **报告。** 给出逐设备对照表：训练产物各项"相同或不同"，评分窗总数、相同窗数、首个不同窗的位置与两边数值。全部相同才判通过。
6. **不同时的处置。** 不同即缺陷，上报，不解释、不调参、不放宽判据。首个不同窗的位置是诊断的起点：若从第一个窗口就不同，看训练产物；若从中途某处开始不同，看该处前后的数据流（缺轮、重复、顺序、缓冲边界）。

**跨语言比较的例外（10 月 26 日补充）。** Java 与 Python 对超越函数（例如
log1p）的实现在少数输入上相差一个最低有效位，经分位数、中位数等运算后差异
约为十的负十五次方。因此 Java 实现与 Python 参考实现之间的比较，对经过超越
函数的连续统计量采用十的负十二次方的容差，对离散结果（事件清单、分箱统计量、
状态转移）仍要求逐条相同；同一语言内（集群上的 Java 对 Java）一律逐位。
本项目首次遇到此事是数据层光照通道的 log1p 变换。

## 第七节：写进论文时怎么表述

在实验方法一节中写明：所有涉及系统结构而非算法的改动（训练线程化、状态恢复、分区放置、重放分段）均以"逐位等值"验收，即在固定输入、种子与单线程数学库的前提下，改动前后的全部中间产物与输出逐位相同；并给出一次恢复实验的逐位相同作为状态一致性的证据。这比"误差在容差内"的表述更强，也回答了审稿人关于容错恢复是否改变检测结果的常见问题。
