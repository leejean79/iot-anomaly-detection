# Ruling: Eight Findings from the M7 Offline Experiment

> 接收方：代码开发 agent。

## 总判断：八项中有五项出自同一个原因，它不是规则的缺陷，而是开环实验的性质

本次离线实验是开环的：命令只发出、不执行，数据层的参照始终是三月一日至八日的标定周。数据层阶段已经查明，气体自三月十四日起相对标定周抬高、温度分段偏离（理论回传第二十三条）；在开环里这些偏离一旦进入就永远不结束，于是从三月中旬起多数设备长期处于"漂移"状态，而"漂移"在归因优先次序里压过瞬态、现场条件与异常，在"只发一次"规则下又挡住后续命令。第一、二、四、五项以及第三项的一半都是这个机制的直接后果，第六项是它的一个变体。示意图的上半幅画的是这一机制，下半幅画的是闭环下同一条规则会给出的结果：零级在三月十六日前后生效、参照重新冻结，气体通道在新参照下回到正常，三月事件成为新的一段偏离，八台各发一条命令，四月的共模时段落在正常状态上、可以被归为环境事件。

所以本次实验回答的问题是"决策函数在不执行命令时的行为"，片段矩阵里那些写给闭环的预期（三月事件八条命令、四月时段归为环境事件、注入归为异常）在开环里本来就不可能成立——交接文档把它们写成本阶段的预期是设计会话的错误，不是实现的错误。按"不迎合"约定，规则不改，预期改为两档：开环的预期按本裁决书重写，闭环的预期留给适应执行第二批末尾的全量重放与"链式离线实验"（见末节）。各项裁定如下。

## 第一项：三月事件只有两条命令

**裁定：开环的正确结果，记录。** 另外六台在三月二十一日之前已因气体抬高或温度进入"同一段偏离"，按"只发一次"被挡，这正是该规则在开环里的设计用途（没有它，B、D、E、H 每两天一条）。请补两个数：不带"只发一次"规则的对照跑里三月事件有几条命令（应为八台各一条，若不是，列出原因）；带规则时六台各自的首次命令日期与触发通道。闭环预期（八台各一条）转到链式离线实验。

## 第二项：四月五个共模时段与傍晚气体上升几乎没有"环境事件"

**裁定：开环的正确结果，记录；七条命令逐条分类。** 多数小时被已有的漂移状态覆盖是优先次序的既定行为。落在这些时段上的七条数据层命令是否算长瞬态实例（示意图丙型），按触发通道的偏离段起点判断：偏离段在该时段内进入、并在时段结束后回落的，是丙型实例；偏离段在时段之前已经进入的（例如气体自三月十四日起的抬高）与时段只是重合，不算。请逐条列出触发设备、通道、偏离段起止日期与判定。

## 第三项：C 的正午没有一个小时归为"现场条件"

**裁定：记录为数据事实，规则不改；补一项敏感性记录。** 两个原因分开记：其一，多数正午小时没有检测标志——上下文通道标志要求六个十分钟窗口中至少三个超阈，C 正午的超阈窗口可能达不到三个；其二，有标志的小时处在温度触发的漂移期内（设计会话此前预见的是气体，记录更正）。第一个原因里 p_ctx 取二分之一是设计会话给的整数默认值，请在判读口径里加一条敏感性记录：p_ctx 取六分之一、六分之二、六分之三时 C 正午各小时的标志有无与归因，只作记录，默认不改。"现场条件"这个标签在本数据的默认规则下没有实例，这本身是一条数据事实，写入报告与开发设计日志。

## 第四项：平稳日上有七条命令与一千零九个漂移小时

**裁定：记录，与理论回传第二十三条一致，不是新发现。** 上下文通道阶段的平稳日清单以训练期为参照，数据层的偏离以标定周为参照，两套口径不同；数据层阶段已查明四十六个可判平稳设备日中四十五个有长记忆事件。片段矩阵"平稳日无命令"的预期在标定周参照下不成立，这与理论第五项验证被推迟的理由相同，闭环下重新检验。

## 第五项：十四段注入所在小时没有一个归为"异常"

**裁定：开环的正确结果，但要补两件事。** 其一，逐段列出所在小时的归因与原因：若为"漂移"，写明是哪台哪通道的漂移期；若为"质量问题"，写明是缺轮还是守卫打标超门槛，以及这与注入本身是否有关（注入段若引起守卫打标，是注入设计与守卫的相互作用，要单独记录）。其二，确认告警载荷里保留了该小时的点通道与上下文通道标志：单一主标签被漂移覆盖时，异常信号仍要能从载荷里查到，这是告警格式的要求，不是归因规则的改动。

## 第六项："任一触发回落即结束偏离"的连带效应

**裁定：改为按触发信号类分别结束，这是交接文档写得不够准的地方。** "同一段偏离只发一次"的用途是替代闭环里参照重新冻结的效果，而重新冻结作用于数据层的参照，所以段的结束应当看触发该命令的那一类信号本身：由数据层某通道触发的命令，该通道回到正常才结束；由性能层触发的，性能层确认回落才结束；由两层同报触发的，以数据层通道的回落为准（数据层是慢的、长记忆的那一层）。这样性能层不再间接决定数据层命令的有无。改动后重跑，并把 G 在四月十七日那条命令在改动前后的有无写明。

## 第七项：是否追加决策节拍一小时的扫描

**裁定：追加，只作记录。** 代码开发 agent 给出的事实（性能层十五段确认持续满六小时、其中八段始于共模时段）说明这一档正好量化澄清一里的权衡：节拍一小时加等待六小时时，这些确认段都会构成持续并发命令，其中始于共模时段的八段就是被长瞬态骗到的次数。扫描结果写进判读口径第九条的表。

## 第八项：三月三十日的机队级爆发落在全机队缺轮十二分半钟的小时内

**裁定：记为质量问题是正确的；按"数据出处优先"约定追查一步。** 全机队同时缺轮十二分半钟是采集或传输中断的形态，爆发多半是中断之后窗口内邻居关系断裂的产物。请代码开发 agent 核对原始数据集在该时段是否本来就缺（是数据集的缺口还是重放的缺口），并查数据集随附材料有无该日的说明；结论登记为数据事实候选"三月三十日二十点二十分前后全机队缺轮约十二分半钟，机队级爆发为其产物"。数据层阶段的待核实项由此关闭。

## 末节：链式离线实验

本次实验证明了一件事：对一个会改变自身参照的系统，开环实验只能检验决策函数的机械正确性，检验不了它的效果。适应执行第一批的离线模拟器（按命令重估参数、重新冻结参照、重算数据层状态）交付之后，把两者串起来做一次"链式离线实验"：决策函数发命令，模拟器执行，数据层状态在新参照上重算，决策函数继续——逐日推进到四月三十日。片段矩阵的闭环预期在这里检验；它放在适应执行第二批的交接文档里，先于全量重放做，因为它便宜且可以反复跑。本阶段（聚合决策部分）的收口以开环结果为准：验收项一至五不变，判读口径的预期按本裁决书改写为开环预期。
