## 第一项验收（V-M6b-1）

**通过。** 单元测试一百七十七个全部通过；开环默认配置（命令只发出、不执行）重跑的三份日志与聚合模块收口基线逐字节相同；二十三种配置逐条相同且 `equality.md` 与收口时逐字节相同；合成六次换版本的五种配置下 Java 与 Python 三份日志逐条相同，告警与命令条数的变化说明版本分支确实被执行到。合成换版本这一招是对的：开环输入走不到的分支必须另造输入去走到，这一做法写进逐位等值方法手册作为一条通例——"等值核对必须覆盖到每一条分支，走不到的分支用合成输入走到"。

## 五条写法的裁定

**第一条，当前版本取最近一个有读数的告警节拍内各轮版本号的最大值：确认。** 一个节拍内最多跨一次版本，取最大值即取新版本。

**第二条，过滤范围包括"该日可判"：确认。** 在场设备数与回落判定都只看同一版本的日结论，与数据层"换参照后从该轮所在当地日重新开始"的定义一致；生效时刻不在日界上的"重估日"本就不可判。

**第三条，段在第一个出现新版本的告警节拍上结束，不等到下一个决策节拍：确认。** 这正对应闭环运行（命令被执行、结果回到输入）里参照重冻则段结束的含义；性能层的段不受影响，因为上下文通道的版本是训练版本。

**第四条，离群率爆发与日界复核的"当日不可判"不过滤：确认。** 爆发不是日结论；复核报告的是当日自己的记录。

**第五条，现场条件的参照宽度与钟点基线都取首次冻结时的值、换版本后不更新：确认，并更正设计会话此前的一句话。** 10 月 29 日的裁决书（实现前五点说明第一点）曾写"换版本后只有门槛随新参照直方图更新"，现在改为不更新。理由：参照宽度在"同步变化"里只是一个度量尺度，与钟点基线配套；基线取自首次冻结后的十天，尺度也应取同一时期的参照，两者才在同一坐标上；而且零级之后的新参照若取自短窗口，其宽度可能远小于标定周（数据事实第三十九条候选），用它作尺度会让"同步变化"在换版本后处处成立。这一条写进聚合模块交接文档的更正记录。
