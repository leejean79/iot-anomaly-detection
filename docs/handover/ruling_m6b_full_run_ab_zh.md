## 第一项：运行 b 证实了迟到随墙钟变化，重跑的裁定不变

运行 b 迟到的是同一组六条命令，但到达时上游的水位线比运行 a 晚约八点五小时事件时间（冷启动排队的墙钟不同）。两次输出逐位相同只是因为这六条的迟到余量都在一天半以上，集合碰巧一致；一条生效时刻落在边界附近的命令在两次之间就可能一次迟到、一次不迟到。所以第二段等值这次的"通过"不是可靠的通过。按下游水位线限速并重跑的裁定不变。顺带记一笔好消息：等值第一段（三月八日至二十三日，与链式离线逐条相同：告警九百六十五、命令十二、复核二十六、离群轮一千四百四十九、日记录六百）与第二段（九类输出逐行相同）都通过，说明在线回路本身是确定的，问题只在重放的节奏。

## 第二项：二级观察窗与一级冷却按"发出"而不是"完成"起算

代码开发 agent 指出的另一种表现成立：聚合模块在发出一级命令时自行推算完成时刻，由此开始一级冷却并打开二级观察窗，不管那条一级有没有执行；运行 a 里四条未执行的一级（三条迟到、一条被忽略）都这样打开了观察窗。**裁定：与前一裁决书第三节的改动合并解决——上下文模块把"一级切换完成"（含模型代数与切换时刻）作为事件发布，聚合模块以收到的完成事件为准起算一级冷却与二级观察窗；没有完成事件的一级不开冷却、不开观察窗。** 完成时刻在事件时间上就是提交时刻加零（切换按事件时间定义），所以这不改变确定性。链式驱动同步。

## 第三项：影子评分表的判读（选项一的再验证）

运行前写定的预期是"零级之后影子超阈率（按当前版本标准化）明显高于正式超阈率（按训练版本）"。实测：有在线窗口的二十七条零级命令中，七条影子高于正式，四条影子明显低于正式（D 三月二十三日 0.229 对 0.015，E 三月二十三日 0.082 对 0.000，F 四月四日，D 四月七日），其余相近。**预期只部分成立，如实登记为数据事实第四十四条候选，并给理论回传第二十七条加一款。** 判读：影子低于正式的四条里，D 与 E 三月二十三日的命令正是三月事件的零级——那是一次真正的位置平移，重估恰好是漂移的逆，跟随零级让上下文模型的超阈率从两成三降到百分之一点五；影子高于正式的七条多落在四月的瞬态时段附近，重估不是漂移的逆，跟随零级伤害模型。也就是说，"上下文通道是否跟随零级"不该是全局的开关，而取决于这次零级是不是位置平移的逆。影子评分本身就是判断依据：零级生效后若影子超阈率连续 K 天低于正式超阈率，说明新坐标更适合模型，可以切换版本（相当于一次零代价的坐标切换，不重训）；反之保持训练版本。这是第三批的候选设计"影子评分驱动的版本切换"，不在本批做。影子评分表在重跑后重出。
