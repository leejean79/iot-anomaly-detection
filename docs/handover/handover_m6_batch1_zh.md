## 第零节：五项设计决定（已确认）

**决定八：命令回路经 Kafka 命令主题回到上游。** 数据接入、点异常检测、上下文异常检测三个算子各自按设备键连接命令主题 `synergia-adapt`；命令存入受检查点保护的状态，在事件时间到达生效时刻时执行；执行之后的输出携带参数版本号；在生效时刻之后才到达的命令记为迟到并计数，"迟到命令数为零"加入重放完整性断言（第八条）。

**决定九：原始缓存改为紧凑格式、深度七天。** 每轮五个单精度数加时间戳与掩码，约两兆每台，受检查点保护；深度参数化，默认七天。

**决定十：零级的执行定义。** 数据接入模块用缓存中生效时刻之前最近 D 天（默认一天，参数）的轮重估五个通道的中位数与四分位距，重估窗口剔除守卫打标的轮；换版本后用同一窗口重新冻结数据层的参照直方图并附在第一条新版本轮上；点通道清空状态、从缓存按新参数回填一个窗口；上下文模块的模型与阈值不动，只在输出上换版本号；零级之后一天冷却期（冷却期由聚合模块执行，本模块只记录）。

**决定十一：第一批的验收。** 单元测试；离线模拟（G 的光照与气体抬高两个用例）；短重放等值（手工下发同一条命令，在线执行与离线模拟逐位相同，迟到命令为零）；性能（缓存状态大小、回填耗时）。

**决定十二：第二批的范围预告。** 一级（热启动、最近 N 天净化样本、旧模型继续服务、原子切换）、二级（回收集态并重新冻结）、开放问题第十二条的实验、决策矩阵中一级与二级的格子、全量重放。本阶段不做。

## 第一节：任务的一句话说明

让一条带生效事件时间的零级命令能够从命令主题进入三个上游算子，在事件时间到达生效时刻时由数据接入模块重估标准化参数并换版本、重新冻结数据层参照、由点异常检测模块重建状态、由上下文模块换版本号，整个过程在两次运行间逐位相同，迟到命令为零。

回路的下半段（聚合模块发命令）在另一份交接文档里；本阶段做的是上半段：命令主题、三个算子对命令的消费、生效时刻的执行。

![零级的含义](figs/m6_l0_explained.png)

零级靠重估中位数与四分位距把位置平移与尺度伸缩映回模型学过的标准化分布；它对分布形状的变化无效，这一局限由聚合模块的"不回落则升级"处理，留待第二批。

![命令的确定性](figs/m6_command_determinism.png)

命令经 Kafka 回到上游的到达时刻是非确定的；只有把执行锚定在生效事件时间上，两次运行才能逐位相同。

## 第三节：命令契约

命令主题 `synergia-adapt`，一个分区，键为设备号。每条命令的字段与含义如下表。

| 字段 | 含义 |
|---|---|
| 设备号 | 命令作用的设备。 |
| 级别 | 本阶段只有零级；字段保留一级与二级的取值供第二批使用，收到非零级命令时本阶段记录并忽略。 |
| 生效事件时间 | 算子在事件时间到达这一时刻时执行命令；它必须晚于决定时刻。 |
| 决定时刻 | 聚合模块做出决定的事件时间。 |
| 命令序号 | 聚合模块按设备维护的序号，从一起计；数据接入模块执行后把它作为新的参数版本号（冻结时的版本号为一，所以第一条命令的序号应为二；聚合模块的序号从二起计，或数据接入模块取序号加一，两种写法任选其一并写明）。 |
| 决定依据 | 触发事件的引用、同报设备数、范围、归因标签、时间形态；本模块原样写入执行日志，不解释。 |

手工验收时，命令由一个小工具写入命令主题，字段与上表相同。

## 第四节：各算子的改动

**数据接入模块。** 其一，原始缓存改为紧凑环形缓冲：每轮五个单精度读数（光照为 log1p 域之前的原始值，删失标记在掩码里）、事件时间戳、守卫掩码；深度七天（参数）；受检查点保护，序列化只写已用部分（沿用数据层阶段日缓冲的做法）。其二，连接命令流：命令到达时若其生效时刻早于当前水位线则记为迟到并计数，否则存入状态；注册生效时刻的事件时间定时器。其三，定时器触发时执行零级：取缓存中生效时刻之前最近 D 天（默认一天）的轮，剔除守卫打标的轮，按与冻结时相同的算法重估五个通道的中位数与四分位距（光照在 log1p 域，删失值不计入；算法必须与标定冻结共用同一个函数，这是逐位等值的前提）；版本号换为命令序号；用同一窗口按数据层阶段的做法重新生成参照直方图，附在第一条新版本轮上；此后输出的标准化轮携带新版本号。其四，执行日志：每条命令的到达事件时间、生效时刻、是否迟到、重估窗口的轮数、新旧参数、新版本号。

关于剔除点通道标记为离群的轮：理论第十四条协议要求重估前做训练集异常剔除。数据接入模块在上游，拿不到点通道的离群标志；本阶段只剔除守卫打标的轮，依据是中位数与四分位距对百分之几的离群轮稳健。离线模拟中另算一遍剔除离群轮的版本并与在线定义并排（判读口径第四条），若两者差异超过逐位等值方法手册里"同一实现"的容差，这一条带回设计会话。

**点异常检测模块。** 连接命令流，同样的迟到判定与定时器。定时器触发时清空该台的全部窗口状态，从数据接入模块的缓存取生效时刻之前一个窗长（一小时）的轮，按新参数标准化后回填，回填的轮只用来建立邻居关系，不发出判定（它们的判定早已发出）；回填完成后的第一条新轮起正常判定，输出携带版本号。回填需要点异常检测算子能读到缓存：实现为数据接入模块在执行零级时把回填所需的一个窗长的轮随第一条新版本轮一并下发（作为该轮的附件，与参照直方图同一机制），点异常检测算子收到附件即回填，这样不需要跨算子访问状态。

**上下文异常检测模块。** 连接命令流，只做两件事：记录命令、从生效时刻起输出携带新版本号。模型、阈值、窗口、相位都不动。连接命令流的目的是让第二批的一级与二级有现成的入口。

**数据层漂移监测模块。** 不连接命令流；它从第一条新版本轮的附件里拿到新参照直方图，替换参照、清空状态转移状态与当日缓冲，从该轮所在当地日重新开始；日记录里加版本号字段。性能层模块不改。

**断言。** 重放完整性断言加第八条：迟到命令数为零。三个算子各自计数，作业结束时汇总。

**参数。** 缓存深度、重估窗口 D、命令回路总开关（关闭时不连接命令流，输出不带版本号字段或带常量一，二者选其一并写明，使"不启用则逐位相同"可验）。

## 第五节：离线模拟

**工具。** Python 参考实现读原始数据、冻结参数与一条手工命令，按第四节的定义算出新参数、新参照直方图与回填窗口；再用数据层阶段的离线工具在新参照上重算命令之后的数据层状态转移，用点通道离线探针在新参数上重算命令之后的离群率。Java 离线运行器共用在线的重估函数，与 Python 逐位比较（中位数与四分位距的计算没有超越函数，不设容差）。

**两个用例。** 其一，G 的光照：标定窗口被连续人工照明污染（数据事实第三十四条），数据层光照通道自冻结起持续偏离；手工命令取生效时刻为三月二十五日的当地日界（与聚合模块短重放区间一致）。其二，气体抬高：B 的气体自三月十四日起相对标定周抬高（第三十六条候选）；手工命令取生效时刻为三月十六日的当地日界。

**判读口径**（运行前写定，均为测量项）：

1. 重估前后五个通道的中位数与四分位距，并与标定周的值并排；重估窗口的轮数与剔除数。
2. 命令之后数据层该通道的状态：G 的光照是否在新参照上回到正常并保持；B 的气体是否回到正常，以及三月二十二日事件到来时是否重新进入偏离（这是"零级之后数据层仍能看见下一次漂移"的检验）。
3. 命令之后点通道的离群率：与命令之前一天、与不执行命令的同一天并排；回填窗口结束后第一小时的离群率单独列出（状态重建的瞬态）。
4. 剔除离群轮与只剔除守卫轮两种重估的参数差，以及由此引起的离群率差。
5. 理论第二条风险的检验：上下文通道在命令之后的主分分布（中位数、第九十五百分位、超阈率）与命令之前一天并排；注入段若落在命令之后，列出召回表的变化。模型不动，这一条量的是"输入换了标准化之后模型是否仍然适用"。
6. 重估窗口 D 取一天、三天、七天时第一、二条的变化（只作记录，不改默认）。
