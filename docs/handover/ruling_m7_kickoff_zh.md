## 第一项：离线输入由前两个阶段的离线产出拼装

**裁定：按建议做，不开全量重放。** 性能层事件取 `docs/m5b/grid/events/c0.99_r0.5_10min_k36_with_injection.csv`（已证明与在线逐条相同），数据层的状态转移、爆发、日记录与质量取 `docs/m5a` 下"不剔除注入"的那一遍（已证明 Java 与 Python 逐条相同），十分钟入口轮数取 `denominators.csv`。新增一个在本地 Mac 上运行的提取脚本，产出每台每当地小时的轮数、入口轮数、守卫打标轮数与五个通道的小时均值（光照在 log1p 域，删失值不计入），做法与数据层离线第一步相同。报告写明每路输入的出处。短重放（验收项三）用真实的在线输入核对，这一步补上"输入出处统一"的缺口。

## 第二项：性能层的确认没有结束时刻

**裁定：做法甲。** 本模块消费同一路上下文主分，确认之后按与持续性核对相同的规则——取最近六个元素的中位数，一旦不高于确认事件携带的门限（参照加 ρ 倍历史标准差）即记为"确认已回落"——维护每台的"已确认未回落"状态。性能层模块不改。

这是交接文档的空白：设计会话在写"已确认未撤销"时沿用了性能层的词，而性能层的撤销只针对候选。开发决策登记：性能层的确认在性能层内部没有结束事件，"确认的回落"由聚合模块定义，用的是与候选核对相同的统计量，这使"回落"与"确认"在同一尺度上可比。这一条同时解决开放问题第十四条的一半（另一半，撤销命令，由时间形态门控使其不需要）。

## 第三项：离线实验中命令不被执行，同一段偏离会反复发命令

**裁定分三条。**

其一，确认零级命令执行后数据层的参照随之重新冻结：这是适应执行模块的定义（随发的交接文档决定十），重新冻结的参照取与重估标准化参数相同的窗口，数据层的状态在新参照上重新开始。在真实闭环里，一段偏离在零级生效后自然结束。

其二，增加一条规则，写入交接文档第四点二："同一段偏离只发一次零级命令"：某台收到零级命令后，直到触发它的那一类信号至少回落一次（数据层该通道状态回到正常，或性能层确认已回落）之前，不再对该台发零级；冷却期仍作为下限保留。这条规则在真实闭环里几乎不起作用（参照重新冻结后偏离会结束），它的用途是让离线实验与真实闭环的命令数一致，也防止真实闭环里重估之后仍不回落的通道每两天被重估一次——那种情况应当升级而不是重复零级，升级留待第二批。

其三，离线实验的命令日志仍标出"同一段偏离的第几次命令"，并额外跑一遍不带"只发一次"规则的结果作为对照（只作记录），这样 B、D、E、H 气体每两天一条的现象留在报告里，作为"零级若不执行会怎样"的证据。判读口径按首次命令统计。

## 第四项：小时节拍引用了当时还不知道的日结论

**裁定：按建议更正，这是交接文档的错误。** 小时告警只用整点时已知的信息：归因第一条的"当日不可判"改为"该小时不可判"；归因第三条与数据层标志的"本日界或上一日界"改为"上一日界或再前一个日界"，即小时 h 所在日之前的两个日结论；分布切换的静默改为：小时 h 有爆发标志，且前两个日界之一有进入偏离，则静默。另在每个日界对当日的小时告警做一次复核，写入复核日志（与命令日志并列）：补标当日不可判的设备，把当日爆发小时的"异常"改记为"分布切换"（若该日的日结论是进入偏离）。复核不改已发出的告警；离线与在线的复核日志逐条相同也是验收项一与三的一部分。

## 第五项：点通道门槛的推导期

**裁定：用平稳日参照期（三月八日至十七日，0.72 版裁决）各小时离群率的第九十九百分位。** 由离线工具推导、写入报告。上下文通道的固定门槛不受影响。

## 第六项：上下文通道与性能层从三月二十四日起才有输出

**裁定：接受，报告逐段注明当时可用的信号路数。** 片段矩阵的预期据此修正：三月事件的"持续"预期由数据层连续两日偏离满足（三月二十三日或二十四日的日界），性能层的确认跨日界只可能在三月二十五日之后；气体抬高一段只有点通道与数据层两路。这不改规则，是对预期的读法。

## 第七项：共模门槛在在场设备很少时的取整

**裁定：全局另设至少两台的下限，并在报告中单列在场设备少于四台的小时。** 在场一台时不存在"全局"这个概念，它的标志一律记为局部。

## 第八项：现场条件的连续天数与 C 日照直射的预期

**裁定：改为累计计数。** "最近七天中该当地小时至少有 K_site 天（默认三天）出现点通道或上下文通道标志"，并且当日该小时有标志、此前的计数不少于 K_site 减一。转为"局部漂移候选"的条件相应改为"最近十四天中至少 K_site_drift 天（默认七天）"。第七节的预期改写为"C 正午从累计第三次起归因为现场条件"。交接文档原来的连续计数是设计会话没有对照 C 的日期清单写出来的错误。

## 第九项：同步变化的可执行定义

**裁定三条。** 其一，"同设备另一个通道"排除气压与湿度。其二，光照在 log1p 域比较，删失值不计入均值。其三，取做法甲，并简化比较的基准：在线算子拿不到标定周各当地小时的均值，所以"同步变化"的定义改为"另一通道在该小时的小时均值与参照直方图的中位数之差，超过参照直方图 P90 减 P10 宽度的二分之一"。倍数取二分之一的依据是：正态分布下四分位距约为 P10 至 P90 宽度的零点五二六倍，所以这个门槛与"一个四分位距"相当。离线实验另外算一遍用"标定周同一当地小时的均值"作基准的版本，与在线定义并排（只作记录），以便看到丢掉日内基线的代价。数据接入模块不改。

## 第十项：其他细节

1. 点通道小时离群率的分母取该小时的入口轮数，分子只取到达滑动步的判定；"该小时轮数少于标称一半则点通道标志不可算"与"缺轮超过百分之二十则归因为质量问题"两个门槛都保留，含义如建议所述。
2. 参数版本号：命令携带的是聚合模块按设备维护的命令序号（从一起计，受检查点保护）；数据接入模块执行时把该序号作为新的参数版本号，并在之后的标准化轮上携带。对接规则写在随发的适应执行交接文档里。
3. 生效提前量在短重放（一百二十倍速）上取默认值一天。
4. 在线状态按建议补齐，体积在验收项五实测。
5. 短重放区间沿用三月二十四日至三十一日；该区间内 G 的光照应当在某个日界触发零级命令，请在等值报告中指出那条命令。

## 对代码开发 agent 的一点说明

开工核对里有一句"第三节的零级执行后数据层参照是否重新冻结，依赖适应执行模块的交接文档"，这是对的：两个模块是同时开发的，聚合模块只需要知道三件事——零级会换标准化参数版本、会重新冻结数据层参照、会让点通道状态重建；其余都在适应执行模块里，聚合模块不等待也不检验它的执行。
