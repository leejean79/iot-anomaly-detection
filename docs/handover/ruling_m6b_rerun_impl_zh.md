# Ruling: Five Implementation Choices and Two Gaps before the Full-Replay Rerun

## 五条写法

**第一条，限速读两个算子各子任务当前输入水位线的最小值，读不到或尚未建立时不限速只计数，暂停后以当前墙钟重新起算节奏：确认。** 补一条：连续读取失败超过十二次（一分钟）时在重放器日志里发一条警告，运行结束时把失败次数与暂停次数、暂停总时长一起写进 `throttle.txt`。

**第二条，限速开关对照关闭命令回路、聚合模块照常运行、时段三月一日至二十七日：确认。** 推理正确——命令回路打开时关闭限速的那次必然出现迟到，对照证明不了限速本身无害；关闭命令回路后两次逐位相同才是"限速只改节奏不改事件时间输出"的证明。

**第三条，上线事件取新模型第一条评分的窗口末、下线事件取二级生效时刻、一级完成取训练集止点：确认。** 在线与链式用同一时刻，避免差一窗的日界判定分歧，这是对的。

**第四条，抑制的记法（复核类别、改发零级的依据写法、只记录的结论不占"只发一次"标记）：确认。** 每个日界各记一条复核是可接受的，它让抑制持续了几天一目了然。

**第五条，新的链式基线 D7K_up_s（F 三月二十二日的一级改发零级并执行，驱动停在 D 三月二十四日日界的一级，等值第一段延到三月二十五日）：确认。** 前十一条命令与原基线逐条相同、第十二条起因 F 多执行一次零级而分开，这一差异来源单一、可解释，报告里写明。

## 两处空档

**第一处，一级已发出、尚未完成的那几天：取做法二。** 聚合模块把"已发出、尚未收到完成事件"视为重训进行中，期间不发一级与二级，复核类别"一级被抑制：重训进行中"（含数据层触发通道时改发零级，与模型不在线的处理一致）；收到完成事件或"一级失败"标记后解除。再加一个保险：若生效后超过 K_fail 天（默认十四天，参数）既无完成事件也无失败标记，视为失败解除，并写一条 REPORT——限速之后不应再出现这种情况，保险只防止状态卡死。不取做法三，"重训已接受"事件在限速之后与"已发出"等价，多一个事件没有多一分信息。

**第二处，二级的冷却从新模型的上线事件起算七个当地日：确认改为此法。** 与一级的写法一致，也与"按真实状态而不是按命令推算"的原则一致。

## 顺序

一，升级格与抑制规则的 Python 参考实现（合成输入命中每个格与每种抑制，五种配置逐条相同），新基线 D7K_up_s 的 Python 对照；二，限速开关对照上集群（可与一并行）；三，两次全量重放重跑；四，正式验收报告与第二批收口记录。
