# Ruling: Eight Implementation Choices and One Gap in the M6 Batch-1 Online Part

## 第二节八项做法的裁定

**第一项，迟到判定多一个条件：确认，而且这是必要的。** 只按水位线判迟到漏掉了"生效之后的轮已按旧参数处理、但水位线尚未越过生效时刻"的窗口，在那个窗口里到达的命令若执行，两次运行会因到达先后不同而不同。多出的条件正是逐位等值所要求的。两种迟到在日志里分开计数（水位线迟到、已处理轮迟到），断言八取两者之和为零。

**第二项，两个触发点等价：确认。** 单元测试证明两种触发看到同一份缓存、输出逐位相同即可。

**第三项，回填附件挂在第一条点通道会接纳的新版本轮上：确认，并补一项核对。** 同样的问题可能出现在参照直方图上：数据层若也丢弃有缺失通道的轮，挂在第一条新版本轮上的直方图会随之丢失。请核对数据层读取附件是否先于任何缺失过滤；若不是，直方图同样改挂在第一条数据层会接纳的新版本轮上，并把这一条加进 `M5aReferenceReplaceTest`。

**第四项，回填范围与判定屏蔽：确认。** 监测快照的离群率包含回填点，只在报告里注明；聚合模块与数据层的离群率都来自离群记录，不受影响。

**第五项，生效时刻须为滑动步的整数倍：确认，写入命令契约。** 聚合模块的日界满足；手工工具拒绝不满足的时刻是正确做法。

**第六项，缓存精度固定为双精度：确认。** 提取统计表明温度与湿度各有数万条读数不能被单精度精确表示，按裁决第四项的判据只能用双精度；不提供单精度选项是对的，因为它会改变重估结果而违反逐位等值。每台约三兆，八台约二十四兆，请在短重放时实测它与检查点通信帧上限（二百五十六兆）及 JobManager 内存检查点上限（单子任务一百二十八兆）的余量。

**第七项，冻结之前到达生效时刻的命令记日志后忽略：确认，单独计数为"冻结前命令"，不计入迟到。**

**第八项，监测快照不带版本号：确认。**

## 第三节的缺口：聚合模块未按版本过滤日结论

**裁定：在第二批开头补，不在现在补。** 理由：第一批的验收不涉及聚合模块；聚合模块刚以二十三种配置的逐条相同收口，现在改它会让收口基线失效。第二批交接文档的第一项是链式离线实验，按版本过滤是它的前置，届时补上：输入映射读日记录的版本号，决策函数只引用与该台当前版本相同的日结论，Python 参考实现同步；补完后在开环默认配置上重跑一次，三份日志应与收口时逐条相同（开环没有版本变化，这是现成的回归证据）。缺口登记在开发设计日志。

## 第四节的待办

认可顺序：Python 重估移植与逐位比较、离线模拟器与报告、短重放编排、性能测量。离线模拟的原始数据提取需要用户在 Mac 上运行一次，请把命令与期望产出按已有格式写给用户。
