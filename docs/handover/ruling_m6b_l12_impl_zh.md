## 第一节：零级默认值变更的执行（开发决策第十二条）

用户已确认。执行顺序：其一，零级加参数"不随零级重估的通道集合"，默认为湿度与气压，这两个通道在每次零级后沿用冻结参数（中位数与分母都不变），参照直方图中这两个通道的边也沿用冻结参照；其二，链式离线实验补跑乙档加此开关，作为新的闭环基线，运行前写定的预期：命令总数不多于六十，每条命令生效后七天内湿度与气压的连带偏离日数明显低于二百八十四，三月事件与 G 光照的命令时刻不变；其三，Java 与 Python 的零级重估在新开关下逐位核对；其四，之后的短重放与全量重放都用这一默认。理论线不采纳时关闭开关即回到全重估。

## 第二节：七条写法的裁定

**第一条，冷启动的训练版本取提交训练那一刻的当前版本，收集期窗口存原始值、提交时统一标准化：确认。** 这比第一批"逐轮按到达时版本标准化"更符合决定十三的定义，也避免训练集里混着两个版本。后果如实登记：链式乙档里 E 的第一条零级在三月十六日生效、落在收集期内，所以在线时 E 的训练版本是二或三而不是开放问题第十二条实验所用的版本一；第十二条实验选定的默认参数不因此改变，但全量重放中 E 的初始模型与那次实验不可直接比。

**第二条，一级切换的时刻按事件时间定义，复用补遗四的机制：确认。** 旧模型服务到提交重训的那一轮，此后的轮进缓冲、输出水位线保持，新模型标定完成后从缓冲头评分。在事件时间上"标定完成"等于提交时刻，这是两次运行逐位相同的唯一可行写法；代价是墙钟上那一段输出延迟到训练结束，与补遗四相同。生效后侧的写法（旧模型服务 N 天，跨过第 N 天的窗口收满后提交）确认。

**第三条，训练集取上下文模块自己的在线窗口、末轮落在范围内者，历史不足 N 天时训练集变短并记日志：确认。** 与离线实验的窗口边界错开几轮，记录即可。

**第四条，N 天按秒计：确认。** 夏令时切换日差一小时，记录。

**第五条，模型代数：确认。** 一级与二级都不改参数版本号，性能层按模型代数清空；代数也写进告警与命令的决定依据里，供聚合模块判断"一级之后"。

**第六条，冲突与失败：确认，补一条。** 一级重训失败两次放弃、旧模型继续服务，除 REPORT 日志外，在监测快照上标一次"一级失败"，使离线工具能数出来；聚合模块本阶段不消费它。

**第七条，影子超阈率由离线工具从快照汇总：确认。**

## 第三节：决策矩阵升级格的四个问题

**第一问，重训完成的时刻由命令自己算出：确认。** 生效前侧为生效时刻，生效后侧为生效时刻加 N 天（N 由聚合模块的参数给出，与上下文模块的参数同源）。

**第二问，K_up 的起算点与"再次"的含义。** 一级之后的 K_up 从重训完成时刻起算；零级之后的 K_up 从生效时刻起算。"再次"不要求中间先出现撤销或回落——模型代数改变时性能层已清空该台历史，切换之后的任何确认按构造都是新的；零级换版本时数据层状态已清零，新版本上的持续偏离按构造是新的一段。所以写法是：K_up 窗口内开始的新段（性能层确认段或数据层持续段）即为"再次"。

**第三问，级别之间的冷却互不阻止，各级只阻止同级。** 零级的冷却期不阻止一级与二级的决定（它们作用于不同模块），一级与二级的冷却期（重训完成后七天）不阻止零级；一级进行中或待做时的新一级、二级进行中的新命令由上下文模块按第六条忽略并记录，聚合模块照常发出。理由：零级在选项一下不触及上下文通道，两者正交；若全量重放显示交叉触发过多，第三批再加交叉冷却。

**第四问，"两层同报"沿用现有写法：确认。** 同一天性能层持续且该通道数据层同日偏离。

据此，升级格可以动手：只有性能层持续，一级；一级后 K_up 天内性能层新确认段，二级；两层同报，一级；只有数据层持续，零级；零级后 K_up 天内同一通道新持续段，一级。K_up 默认七天。

## 第四节：短重放范围

一级取生效后侧、N 三天，短重放改为三月二十四日至四月三日（十个当地日，一百二十倍速约两小时），对 G 手工下发一条一级命令，生效时刻三月二十九日当地日界：G 二十五日冻结、训练与标定约一天，二十九日起旧模型服务三天，四月一日提交重训，之后两天看新模型的评分与版本号、模型代数、性能层清空。两次运行逐位相同；切换前后每个在线窗口恰好一条评分。

## 第五节：顺序

第一节的开关与链式补跑，第三节的升级格，第四节的短重放，然后全量重放。第十二条实验的逐段召回核对（1.40 版第四项）随短重放报告一并交。
