# 裁决书：开放问题第十二条离线实验的结果能否采信、补跑的口径
# Ruling: Whether the DEV-Q12 Results Can Be Used, and the Supplementary Arms

> 发出方：开发设计会话（开发设计日志 1.39 版，2026 年 11 月 10 日）。
> 接收方：代码开发 agent。
> 依据：`m6b_q12_report.md` 与其表格（2026 年 11 月 9 日）。

## 第一项：判据结果不能用来选定 N 与启动方式

**裁定：本次网格的判据结果不采信为对"重训长度与热冷启动"的回答；采信为一条数据事实。** 三十次重训的平稳段超阈率都在三成到九成六，初始模型只有百分之七，重训之后比不重训坏一个数量级；逐通道诊断把误差归到气压（标定段 0.024 对平稳段 21.1，放大约九百倍），成因是版本三的气压尺度只有三百七十二帕、取自三月十八日至二十四日一周高压平稳的日子，之后天气转为低压，气压在版本三下偏出一到十个尺度。在这种条件下，判据一与判据二比较的是"气压尺度过窄"这一共同缺陷在不同 N 与启动方式下的轻重，不是重训本身的优劣——代码开发 agent 的判断正确。

这条事实的意义比它表面看起来大：第一批证明了零级的窄尺度会破坏不重训的上下文模型，于是采纳了"上下文通道不跟随零级"；本次证明了**一级重训也躲不开它——重训模型按当前版本标准化，当前版本的尺度是零级留下的，窄尺度就这样从零级传给了一级**。选项一只保护了"不重训的模型"，没有保护"重训后的模型"。写入数据事实第三十九条候选的补充与理论回传第二十六条。

**另一处要登记的可能成因。** 一级在三月二十八日生效，训练集取生效前 N 天，N 取七时训练集是三月二十一日至二十七日——正是三月事件本身；N 取三是事件的尾部。重训模型把事件期学成了正常，事件之后的平稳日相对它就成了异常。这与 1.38 版裁决里零级重估窗口跨过变化点的问题（理论回传第二十九条）是同一个问题出现在一级上。逐通道诊断里温度误差也放大了约二十倍（标定段 0.046 对平稳段 1.08），绝对值小于气压但方向一致，可能就是它的痕迹。本次不能分离这两个成因，补跑要把它们分开。

## 第二项：补跑两档，运行前写定预期

**档乙（代码开发 agent 建议的那一档）：湿度与气压的标准化参数换成冻结参数（版本一），其余三个通道仍用版本三；训练集仍取生效前 N 天；同一网格三十次，初始模型沿用。** 这一档对应理论回传第二十六条的选项"天气驱动的只记录通道不随零级重估"。预期：平稳段两个口径的超阈率大幅回落，气压的逐通道误差回到标定段的量级；若回落到初始模型的量级（百分之十以内），则本次结果的成因全在气压尺度；若仍明显高于初始模型（例如两成以上），剩余部分归于训练窗口覆盖三月事件，由档丙检验。

**档丙：在档乙之上，训练集改取生效之后的 N 天（三月二十八日起），N 只取三与七（十四会覆盖四月五日的注入日）；评分的平稳段口径一相应改为训练集之后的七个当地日。** 这一档对应理论回传第二十九条在一级上的形态（训练窗口锚定在变化点之后）。预期：平稳段超阈率低于档乙同 N；召回重新有区分度（初始模型为四段中检出一段尖峰、三段阶跃全检出）。两档都保留逐通道诊断（五个种子）。

两档约十小时，开发机上顺序跑；没有用户需要执行的步骤。

## 第三项：召回与热启动耗时

召回饱和的判断正确：重训模型在四月五日几乎所有窗口超阈，六段全检出不反映能力；初始模型的四段（尖峰一、阶跃三）是本数据上这个模型的真实区分度，记为基线。热启动在三档 N 上轮数与耗时都多于冷启动，与一般预期不符，如实登记；设计会话选热启动的理由是权重连续性而不是省时，这一理由要等补跑之后在干净的条件下检验——若档乙或档丙上热启动在平稳段与召回上都不系统地优于冷启动，一级取冷启动。

## 第四项：并行的工作

**可以先行**：一级与二级在线实现中与 N 和启动方式无关的部分——选项一的版本固定标准化（各版本首轮附参数集、上下文模块按训练版本标准化）、影子评分开关、一级与二级命令的接收与状态机、二级的静默与标记——先写代码与单元测试，N、启动方式与训练窗口的起点留作参数，默认值等补跑裁决后填入。一级训练窗口的起点（生效前还是生效后）由于档丙的结果可能改变，请一并做成参数。

## 第五项：对理论线的话

本次结果把两条修订意见连在一起：零级留下的尺度会传给一级（第二十六条），重训窗口跨过变化点会让模型学到事件（第二十九条）。设计会话的建议是，理论文档对零级与一级的协议都加同一条前提——"用来重估参数或重训模型的数据窗口必须落在变化点之后，并且覆盖每个通道的自然时间尺度；天气驱动的通道不随零级重估"。档乙与档丙是这条建议的直接检验，结果出来后一并带回。
