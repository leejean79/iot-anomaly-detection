## 第零节：八项设计决定（已确认）

**决定一：性能层的输入信号取上下文通道的每窗主分，不再另做聚合。** 理论文档第九条决策要求重构误差先按窗聚合、再送入漂移检测器，目的是避免高度自相关的逐点误差把检验的误报系统性地放大。上下文异常检测模块已经满足了这一要求：每一个评分窗把六十个时间步的掩码均方误差合成为一个数，评分窗与评分窗之间不重叠，于是每台设备每十分钟产生一个元素，每天一百四十四个。选用主分而不是原始误差，是因为主分已经逐台标准化（减去该台的校准中位数，再除以该台的四分位距），八台设备因此可以共用同一组检测器参数，不必逐台调整。是否在十分钟元素之上再按小时取中位数，作为一个可选项放进离线实验，由实验数据决定。

**决定二：检测器按文献实现为一份没有 Flink 依赖的纯 Java 类，供所有标量流复用。** 这是理论文档第十一条决策的要求。算法要点如下（10 月 20 日按论文第四章原页修订，见裁决补充 `ruling_m5b_kickoff_addendum_zh.md`）：滑动窗从三十个元素开始增长，长到上限后滑动；对每一个窗长，按论文式 4.1 预先算出把窗切成历史子窗与新子窗的最优切点比例，这个比例只依赖窗长、置信度与鲁棒度三个量，与数据无关，所以可以查表，方程无解的窗长取对半切分；每来一个元素，按算法 2 先做方差的 F 检验，再做均值的韦尔奇 t 检验（分母按式 4.2 用方差，自由度按式 4.12），两个检验都只在新子窗均值高于历史子窗时报警，F 检验显著而均值未升高时不报警、不清空、只计数；报警后清空滑动窗。作者公开代码在 t 统计量分母与自由度两处偏离论文，只用于交叉核对求根与分位数的数值方法。默认参数：置信度零点九九，鲁棒度零点五（作者代码的默认值；零点一在我们的窗上限内使切点方程无解、退化为对半切分），窗上限取十四天的元素数，在十分钟一个元素时为两千零一十六。t 分布与 F 分布的分位数用 Apache Commons Math 计算，切点比例与两个分位数按窗长预先算成常量表，不进入受检查点保护的状态。

**决定三：报警分候选漂移与确认漂移两级，确认依靠持续性核对。** 文献给出的误报上界是每个元素一减置信度，在每天一百四十四个元素的条件下这不是一个可以忽略的数；而且注入实验证明，两小时的异常阶跃也足以让均值检验显著。理论文档第四条决策的信号侧防线要求对漂移信号做门控与去抖，正是为了挡住这类情况。因此检测器自身的报警只记为候选漂移，随后进入持续性核对：以报警时刻历史子窗的中位数为参照，在接下来的 K 个元素里，如果最近六个元素（一小时）的滑动中位数始终高于参照值加上鲁棒度倍的历史标准差，就在第 K 个元素处发出确认漂移；中途回落就撤销候选；核对进行中出现的新候选照常记录但不打断核对，参照值保持不变（10 月 19 日补充）。K 的默认值取六小时的元素数，即三十六个，它大于注入实验中任何异常的持续时间（最长为两小时加一个窗长），又小于三月事件的持续时间（六天）。这样一来，理论文档第十六条候选决策所说的"瞬态回落对持续增长"的时间形态就变成了一条可执行的规则。候选、确认与撤销三种事件都输出，供聚合模块使用。

**决定四：输出接口。** 新建一个漂移主题，名为 `synergia-drift`，一个分区。每一条事件记录设备、事件时间、级别（候选、确认或撤销）、触发的是均值检验还是方差检验、历史子窗与新子窗各自的均值、标准差与长度，以及以历史标准差的倍数计的漂移幅度。监测快照每六十秒新增逐台的当前窗长、最近一次候选与最近一次确认的时刻。这些事件将来是适应执行模块零级响应的触发输入，本阶段只负责发出，不消费。

**决定五：算子位置与时间语义。** 性能层实现为一个独立的按键处理函数，接在上下文异常检测算子之后，与它处于同一个作业，代理键一对一放置保持不变。它按事件时间消费评分窗；补遗四实现的输出水位线保持保证了评分窗按事件时间有序到达。检测器的滑动窗内容、持续性核对的状态与计数都是受检查点保护的状态；预先算好的分位数表是常量，不进状态。当某台设备冷启动、相位回到收集态时，清空该台的检测器与核对状态。

**决定六：离线实验先行，用已有的评分转储，不重放。** 这对应理论文档第二项验证的室内物联网数据段。三次逐位相同的运行留下了三月二十四日至四月三十日八台设备完整的主分流。实验在这份数据上进行，参数网格为：置信度取零点九九与零点九九九两档，鲁棒度取零点一、零点三与零点五三档，元素粒度取十分钟与小时中位数两档，持续性核对的 K 取十八、三十六与七十二三档，合计三十六种组合；另外用加权霍夫丁漂移检测器以其文献默认参数作为对照基线。每一种组合输出逐台的候选与确认事件清单。判读口径在实验运行之前写定（见第四节），不以结果反推参数；默认组合（置信度零点九九、鲁棒度零点五、十分钟粒度、K 等于三十六）是被检验的假设，只有当它在写定的口径下明显劣于某个邻近组合时才更换，更换时要写明理由。

**决定七：本阶段的在线验收只做短重放上的离线与在线等值，全量运行搭适应执行模块阶段。** 按确认性运行约定，全量重放只在其结果会决定一项裁决时进行。性能层的参数由离线实验决定，在线算子只需要证明"在同一条评分流输入下，在线发出的事件与离线工具算出的事件逐位相同"，这在步骤 C 规模的短重放上就能做到。全量尺度的漂移事件清单在适应执行模块的全量重放上顺带产出。

**决定八：边界。** 本阶段不实现零级、一级与二级响应，不实现数据层监测与邦费罗尼校正（那属于数据层漂移监测模块），不实现跨设备的共模判别（那属于聚合模块），不改动上下文异常检测模块的任何输出。文献算法在报警清空之后需要重新攒够三十个元素才能再次报警，在十分钟粒度下这是五个小时的盲区；按理论文档第四条风险的要求，这个盲区要如实测量并登记，它与一级重训窗口的对齐留给适应执行模块处理。

## 第一节：任务的一句话说明

把上下文通道每台设备的主分流接入一份最优窗口漂移检测器的实现，把检测器的原始报警经过持续性核对分成候选与确认两级并以事件流发出；先用已有的评分转储做离线参数实验，再在短重放上证明在线实现与离线工具逐位相同。

## 第三节：代码改动

**检测器类 `com.leejean.m5.OptWinDetector`。** 这是一个没有 Flink 依赖的纯 Java 类。它用环形缓冲保存滑动窗，用增量方式维护均值与方差，按当前窗长从常量表查出切点比例与两个分位数，执行 F 检验与韦尔奇 t 检验，报警后清空。构造参数是置信度、鲁棒度与窗上限。它的内部状态（窗内容与计数）必须可以序列化，以便放进 Flink 的状态。

**常量表类 `OptWinTables`。** 启动时对三十到窗上限的每一个窗长，预先算出切点比例、t 分布分位数与 F 分布分位数。切点比例按文献的式 4.1 求最大根；当窗长太小、方程无解时，切点比例取零点五。分布函数用 Apache Commons Math 的 t 分布与 F 分布实现。

**持续性核对类 `com.leejean.m5.DriftGate`。** 它实现候选、确认与撤销三种状态转移，K 与参照值的计算方式都可以配置。

**算子 `M5bFunction`。** 这是一个按键处理函数：消费评分窗，更新检测器与核对状态，把事件发到漂移主题，更新监测快照；在设备冷启动时清空。

**作业参数。** 新增置信度、鲁棒度、窗上限、元素粒度（十分钟或小时中位数）、持续性核对的 K，以及性能层的总开关，共六个参数。

**离线工具。** 一个 Python 参考实现 `m5b/optwin_offline.py`，它与 Java 实现读同一张分位数表；一个网格脚本 `m5b/run_grid.py`，负责跑三十六种组合与基线并生成判读表；一个 Java 侧的离线运行器 `OptWinOfflineRunner`，读取同一份评分转储，用于与在线实现做等值比较。

**测试。** 单元测试要覆盖以下内容：分位数表与 Python 参考在每一个窗长上一致，容差取一百万分之一，因为两边使用的分布函数实现不同；在合成流上，均值漂移与方差漂移各一例的报警位置与参考一致；在没有漂移的平稳合成流上，报告实测报警率并与一减置信度这一论文上界并排（10 月 19 日修订：因实现跟随作者代码而非论文公式，上界不作为通过门槛）；持续性核对的三种状态转移；检查点恢复之后滑动窗的内容仍然存活。等值测试要求 Java 离线运行器与 Python 参考在真实评分转储上给出逐条相同的事件清单。

## 第四节：离线实验与判读口径

**数据。** 取三次逐位相同运行中任意一次的评分转储，时段为三月二十四日至四月三十日，八台设备；设备 E 剔除注入区间及其后一个窗长。

**判读口径。** 以下六条在实验运行之前写定。它们都是测量项，不是通过与否的门槛：

1. 平稳日上的确认漂移数，逐台统计。平稳日按 10 月 13 日定义的位置加尺度判据，尺度门槛取三点零。理论预期为零，实测值就是性能层的误漂移率。
2. 三月事件的尾段，即三月二十四日至二十七日这四天：是否出现确认漂移，确认的时刻，触发的是均值检验还是方差检验。要注意六台设备的第一个评分窗末在二十四日当地十八时三十四分到十九时二十三分之间，攒够三十个元素后最早可能的报警约在二十四日二十三时三十分到二十五日零时三十分；B 与 H 分别从二十六日十五时十二分与零时三分才开始评分，它们在这一段的可用部分更短（10 月 20 日更正）。
3. 尺度漂移日，即气体宽度倍数超过门槛的日子（10 月 12 日裁决要求登记的清单）：逐台是否出现确认漂移。理论预期以方差检验触发为主。
4. 设备 C 的日照直射日与傍晚全机队气体上升：是否被记为候选，是否被确认。理论预期是候选可能出现、确认不应出现，因为持续时间短于 K。如果被确认，如实登记，不改 K。
5. 盲区：每一次报警之后的五小时盲区内，是否错过了上述任何一段。
6. 基线对照：加权霍夫丁漂移检测器在同一份数据上的候选数，以及它对上述各段的命中情况。
7. 异常不得被确认为漂移（10 月 20 日新增）：另跑一遍不剔除设备 E 注入区间的数据，对尖峰、阶跃、爬坡、卡死共十四段注入逐段记录是否出现候选、是否出现确认。理论预期是候选可以出现、确认不应出现；六小时爬坡与 K 等于三十六恰好相等，是边界情形，如实记录。

**参数选择规则。** 默认组合是被检验的假设。只有当默认组合在第一条上的误漂移数明显高于某个邻近组合，并且在第二、三条上不比它差时，才更换为该组合。无论换与不换，都要写明理由，并把三十六种组合的完整表格附在报告里。

## 第五节：验收标准

- 验收项一（V-M5b-1）：单元测试全部通过，分位数表与 Python 参考一致，合成流上的报警位置一致，平稳流上的报警率不超过理论上界。
- 验收项二（V-M5b-2）：离线实验报告，包含三十六种组合加基线的完整表格、六条判读口径的逐台填写、参数选定与理由。
- 验收项三（V-M5b-3）：离线与在线等值。在步骤 C 规模的短重放上进行，重放中用重放器已有的阶跃注入把持续时间拉长到超过 K，以触发一次确认漂移；在线发出的事件清单与 Java 离线运行器在同一条评分流上算出的清单逐条相同；评分窗本身与不启用性能层的运行逐位相同，以证明性能层没有改动上游。
- 验收项四（V-M5b-4）：盲区与延迟表，给出报警之后再次可报的最早时刻，以及从持续抬高开始到候选、到确认所经过的元素数与分钟数。
- 验收项五（V-M5b-5）：性能，给出每个元素的处理时延（预期为微秒量级）、状态大小（窗上限乘八字节的量级）与检查点体积的增量。
