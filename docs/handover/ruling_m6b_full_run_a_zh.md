## 第〇节：先说结论

运行 a 是第一次完整的在线闭环：五十二条命令（零级三十六、一级十五、二级一），八条断言六条通过，作业零重启、检查点零失败。两条不通过里，断言七是判据没有考虑二级重建期，改判据即可；断言八是实质问题——六条命令因水位线迟到没有执行，其中三条一级，在线回路从三月二十四日起就不再是"命令都按时生效"的回路。这六条迟到不是算法或判据的问题，是加速重放与异步训练的水位线保持叠加造成的事件时间偏差超过了命令的提前量；在一倍速的真实部署里不会发生。裁定是修重放器、重跑两次，而不是把它登记为事实了事，理由在第一节。运行 b 照常跑完，它的迟到条数是"迟到随墙钟变化"的直接证据，留作记录。

## 第一节：六条命令因水位线迟到没有执行（断言八）

**机理确认。** 代码开发 agent 的重建成立：八台在三月二十四日前后集中进入冷启动训练，两个训练线程下单台训练加标定十三到二十分钟、排队十余分钟；按补遗四，上下文模块训练期间保持输出水位线，聚合模块取各输入的最小水位线，于是三月二十四日的日界比正常晚了二十七分钟墙钟才收，约合二点八天事件时间；标准化算子在上游不受保持影响，重放器照常推进，命令送达时它的水位线已越过生效时刻约四十四小时。这正是交接文档第四点四写的提前量下限条件——提前量必须大于"命令往返墙钟乘倍速加上游与聚合模块之间的水位线差"——而在集中训练期间第二项被放大到两天以上。

**为什么不选登记为事实。** 全量重放是本项目第一次闭环在线运行，它要回答的是"闭环的系统在两个月数据上表现如何"，等值第二段与影子评分都建立在命令按时生效之上；带着六条未执行命令（含三条一级）的运行回答不了这个问题，也不能与链式离线对照。把它登记为事实只会让后面所有数字都带一个脚注。

**为什么不选在到达时执行迟到命令。** 那会让执行时刻取决于墙钟，两次运行无法逐位相同，并且改变了命令回路"锚定在生效事件时间"的语义，这一语义是第一批验收的根基。

**为什么不选只加训练线程。** 它只缩短不消除，仍可能每次运行不同；并且训练线程数是补遗四定下的变量，不与其他改动同时变。

**裁定：重放器按下游水位线限速（可选做法二），两次全量重放重跑。** 规格如下：
1. 重放器每五秒读一次聚合算子的当前水位线（Flink 指标接口）与标准化算子的当前水位线；两者之差超过限速阈值时暂停发送，回落到阈值以下再继续。阈值取提前量的一半，即十二小时事件时间（参数 `--replay-max-skew-sec`，默认 43,200）。
2. 限速只改变发送节奏，不改变任何记录的事件时间，所以事件时间上的全部输出不受影响；这一点用短重放证明：限速开与关两次短重放，评分、判定、事件、日记录逐位相同，只有墙钟时长不同。
3. 迟到命令计数仍为断言八，预期为零；若重跑后仍有迟到，列出每条的到达水位线与差额，再议阈值。
4. 这是重放环境的约定，写进重放完整性的说明：**加速重放时上游与聚合模块的事件时间偏差必须被限制在提前量之内，否则闭环在重放中不成立。** 真实部署无此问题，论文里说明。

重跑的两次运行与本次配置相同，另加第二节与第三节的两处改动。运行 b 照常完成，其迟到条数与运行 a 的六条并排记录，作为"迟到随墙钟变化"的证据，之后作废。

## 第二节：断言七在二级重建期间怎样判

**裁定：改判据。** 处在二级收集期（二级生效时刻起、新模型上线前）的设备在断言七中豁免，单独列出设备、二级生效时刻、预计上线时刻与实际最后输出时刻；并增加一条检查：该设备的上下文输出与性能层事件在二级生效之后确实为零（静默成立）。断言七的原文写于一级、二级之前，没有考虑重建期，这是判据的疏漏，不是数据事实。B 在四月二十三日日界收到的二级命令（一级后七天内性能层新确认段）本身是升级格第一次在线命中，记录。

## 第三节：上下文模型不在线时收到一级命令

**裁定：聚合模块在模型不在线时不发一级与二级，改发零级或只记录；两次重跑一并带上。** 现状（上下文模块忽略并警告，命令照常计入冷却）有两个坏处：一条被忽略的一级占用了冷却期，真正能执行的一级被推后七天；决策日志里一条"已发出"的命令实际什么都没做，事后解读要翻警告日志。改法：上下文模块把"模型上线"与"模型下线（进入收集或二级重建）"作为事件写到监测主题（事件时间为该窗口末），聚合模块据此维护每台的在线状态；模型不在线时，命中一级或二级格的结论降为"只记录"并写入复核日志（标明"一级被抑制：模型不在线"），不计入一级冷却；若同一结论同时满足零级格（例如零级后同通道新段），照常发零级。链式驱动以同样的规则处理（它从评分流的首条时间知道模型何时上线），等值段的截止命令随之后移。F 三月二十二日那条（当时仍在冷启动收集期）与 B 四月二十九日那条（二级重建期）都属此类。

## 第四节：一级切换前验证的两次"会拒绝"

登记。十次一级切换中两次的新旧模型标定误差中位数之比超过三倍（B 四月一日 4.08，H 四月九日 7.22），两台随后的下一次切换比值为 0.35 与 0.50。默认仍关闭、只记录；重跑后再看比值的分布与这两台切换后的超阈率，第三批决定是否启用。

## 第五节：事故与脚本缺陷

JobManager 堆耗尽：检查点在 JobManager 一侧卡住、后续检查点每三十秒堆积一次、十次并存耗尽两千零四十八兆的堆。处置认可：JobManager 进程内存提高到三千零七十二兆，检查点之间最短间隔三十秒，编排在提交前核对两者。写进运行约定。断言七读取无条数上限、规范化摘要全量驻留内存、断言八的指标查询标签重复，三处脚本缺陷的修复认可，它们都不改变作业输出。镜像入口脚本重复追加配置项的现象记一笔。
