## 方法与参数

- **停机段 DF-12**：102.26 小时，结束于 **2022-06-13 02:20 UTC**（即停机始于约 2022-06-08 20:04 UTC）。
- **重放段**：2022-06-05 ~ 2022-06-20（停机前有常态基线、停机后有完整恢复过程），`--speedup 3600`。
- **(R, k)**：k=10；逐设备 R 用任务一定稿值（A/B/H=1.0、E/G=0.75、F=2.25），**C、D 用临时值 1.75**
  （终值待设计会话在 Light 通道层面处置后再定；浪涌分析看的是峰值相对各自基线的倍数与衰减形态，
  临时基线不影响形态结论——见 `m2_rk_calibration.md` 补测结果段）。
- **数据来源**：`synergia-monitoring` 的 M2 快照（`windowEnd>0`），逐设备每滑动步的 `m2OutlierRate`、
  `m2WindowPoints`、`m2McOccupancy`、`m2ColdCleared`（本次为浪涌分析新增的逐窗冷启动清空标记）。
- **分析工具**：`deploy/scripts/syn-m2-surge.sh`（转储 + 调用 `m2_surge.py`）；
  常态基线 = 停机前非空窗口离群率中位数；恢复峰值 = 停机结束后 24h 内最大离群率；
  衰减时长 = 峰值起率首次回落到 ≤ 基线×1.5（基线≈0 设备用绝对下限）所经历的事件时间。

## 四问量化（待六月段重放后由 `syn-m2-surge.sh` 填入）

灌入空窗）；与三月段小停机（状态未被完整清空）的浪涌形态对比。_

## 与既有数据事实的关系（如实报回）

- Light 通道（ch4）的重尾放大是 C/D 常态基线偏高的根因（见 `m2_rk_calibration.md`）；浪涌分析用倍数
  （峰值/各自基线）表述，已对该偏高基线做归一化，故 C/D 的临时 R 不影响"是否爆发"与"是否同时"的结论。
- 若实测与"恢复即爆发、全场近似同时、衰减≈W"的预期矛盾，将在此如实标注并报回设计会话。
