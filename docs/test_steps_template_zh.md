# 交付测试步骤：标准格式

- **版本**：1.0（2026-09-19）
- **适用范围**：本项目每一次代码或脚本交付。**每次交付都必须附带一份按本格式写成的测试步骤**，
  无论改动大小。这是用户 2026-09-19 提出的固定要求。
- **与 CLAUDE.md 的关系**：CLAUDE.md 第 6 节规定了**单个脚本**的五要素（执行环境、调用命令、
  前置条件、期望产出、失败兜底）。本模板是它在**一次交付**层面的展开：一次交付往往涉及多条命令、
  本地与集群两侧、以及「怎样才算通过」的判定，需要把这些串成一条可执行的路径。

---

## 必须包含的七节

### 1. 本次改了什么

逐项列出改动，每项一句完整陈述句，说明改了哪个文件的哪个行为。**同时列出明确没有改的东西**——
尤其是算法参数（半径 R、k、窗口 W/S、标定天数）、标定统计量、M3 代码路径。读者据此判断需要重跑
哪些验证，不需要猜。

### 2. 本地验证

给出完整命令与**期望的具体数字**，不能只写「测试应通过」。

```bash
# 执行环境：本地 Mac，仓库根目录；前置条件：JAVA_HOME 指向 JDK 11
git pull origin dev-claude
mvn -o test            # 期望 Tests run: <N>, Failures: 0, Errors: 0
mvn -o test -Dtest=<新增或最相关的测试类>
```

若本次新增了测试，要写清**这条测试断言的是什么**，以及它失败时的提示信息长什么样——这样用户看到
失败时不必回来问。

### 3. 集群验证

只有确实需要上集群时才写这一节；纯本地改动应明说「本次无需上集群」。写的时候每条命令都带上
CLAUDE.md 第 6 节的五要素，并特别注明**顺序不可颠倒的地方**与**不可省略的参数**。

### 4. 判读依据

**这是最关键的一节。** 要给出一个能一眼判定成败的**具体量**，而不是「看起来正常」。好的判读依据
形如「每台设备的 `slides` 应恰好减少 60」「`Ckpt effective ceiling` 应显示 64.0 MB 且由
akka.framesize 决定」。如果某项无法给出确定判据，就如实写「此项无判据，只能定性观察」，不要用
模糊措辞冒充判据。

### 5. 失败兜底

按已知失败模式分别给出排查方向与下一步命令。对于「看起来通过但其实不可信」的情形要单独点出——
例如指标计数器在作业重启后归零、脚本用管道喂 JSON 却被 heredoc 吞掉、jar 没重新上传导致跑的是
旧代码。

### 6. 回滚方式

给出撤销本次改动的具体办法：`git revert <commit>`，或需要一并回退的配置与容器重建步骤。涉及集群
配置（例如 `akka.framesize`）时，要写清回滚后是否需要重建容器才生效。

### 7. 尚未验证的部分

如实列出本次**没有**验证到的地方，以及为什么。例如「逐子任务峰值未实测，因为 Flink 1.13 的
details 响应不含该字段」。**不要用已验证的部分掩盖未验证的部分。**

---

## 五条写作纪律

**第一，不把推断写成结论。** 没有独立测量过的机制，要标明是待验证的猜想。本项目已有三次
「从单个异常数字反推机制、随后被实测推翻」的记录，判读依据一节尤其要守住这条。

**第二，交付 shell 脚本前先跑 `bash deploy/scripts/lint-scripts.sh`。** 这些脚本在 Linux 上写、在
macOS 上跑，而 macOS 自带 bash 3.2 对多字节字符的处理与新版 bash 不同：`"$FRAME（期望值…）"`
在新版 bash 下正常，在 bash 3.2 下会把全角括号的首字节并进变量名，配合 `set -u` 直接报
`unbound variable` 并中断。这类问题在开发机上复现不出来，只能靠静态检查拦住，所以它是交付前的
必跑项，不是可选项。

**第三，命令必须可以直接粘贴执行。** 不写 `ssh -i "$SSH_KEY" "$SSH_USER@$NODE_MASTER_PUBLIC_IP"`
这类展开形式，一律用主机别名 `fa-master` / `fa-worker1` / `fa-worker2`（见
`docs/cluster_runbook.md` 前言的登录约定）。路径写实值，不留需要读者自行替换的占位符，除非确实
因人而异并已注明。

**第四，命令要写在回复正文里，而不是只给文档路径。** 用户执行时不应当需要回翻历史消息或打开
文档去拼命令——回翻本身就是出错来源。每次交付都在回复里给出**完整、按顺序、可直接粘贴**的命令
序列，即使这些命令同时也写进了仓库文档。文档负责留档与下次会话交接，回复负责本次执行。

**第五，阶段实验前先复位环境。** 凡是要上集群跑实验的交付，测试步骤的第一条命令都应是
`bash deploy/scripts/syn-reset-env.sh`，让核对表的退出码成为硬门槛。
