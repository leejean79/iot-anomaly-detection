## 三、成因观察（只观察，不裁决）

**变换达成了既定目标——C、D 回到带内。** 原来的两台过度活跃设备（Light 重尾放大所致）被 log1p 干净
地拉回：C 落 R=1.0（0.257%，最接近带中心），D 落 R=0.75（0.168%）。诊断得到直接验证。

**但出现两个连带效应（§9 如实报回）：**

1. **变换把整个机队的点通道普遍压安静了。** log1p 对全部八台统一施加，也压缩了本来规矩设备的 Light 维；
   F 骤降 49×、E 降 5×，连同一直安静的 A/B/H，导致 **8 台里有 5 台（A/B/E/F/H）现在低于 0.1% 带下沿**、
   被判"分辨力疑似不足"。**变换后的 [0.1%,0.5%] 带 + k=10，对多数设备变得够不到。**

2. **G 反转成唯一的过度活跃设备（↑8.5×）。** 这是最值得注意的一点：G 是唯一离群率**上升**的设备，且升幅很大
   （R=1.75 仍 0.696%，全网格都在 0.5% 以上）。由于 log1p 只压缩 Light，G 的上升说明 **G 的离群信号不在
   Light 维、而在其它通道**——Light 被压缩后，五维距离的相对权重重新分配，G 在非 Light 通道上的变化就凸显了
   出来。换言之，**G 与 C/D 相反：C/D 是 Light 假象，G 是非 Light 的真实活跃**。变换前 G 被 Light 的尺度
   "淹没"，变换后才暴露。这条对 M7（全局/局部判别）尤其有参考价值。

## 四、移动超过一格的设备（补充指令二第三步要求）

- **F（+2.25→0.75，−6 格）**：变换前是靠大 R 压 Light 重尾才勉强落带的临界设备；变换后 Light 重尾没了，
  F 成为最安静的设备（0.030%），机选回落到网格最小 R。
- **D（1.75→0.75，−4 格）**：从 4.7% 的头号过度活跃，直接落到带内偏安静端（0.168%），Light 假象是其
  过度活跃的全部来源。
- **G（0.75→1.75，+4 格）**：唯一向大 R 移动的设备——因其活跃在变换后才显现，需要更大半径才压到带上沿附近。
- **C（1.75→1.0，−3 格）**：同 D，Light 假象消除后落到带中心附近，取值从容。

## 五、交回设计会话的裁决点（不自行决定）

1. **总体**：log1p 变换按预期修好了 C、D（Light 假象），但把机队整体压安静，使 [0.1%,0.5%] 带 + k=10
   对 5/8 设备不可达。请裁决：接受"多数设备点通道近乎静默"（与最初 A/B/H 同处境），还是相应**下调目标带**
   或**减小 k**，让更多设备落回可判别区间？
2. **G（新过度活跃、且为非 Light 来源）**：是接受 R=1.75 的较高基线，还是像当初查 C/D 那样，对 G 做一次
   逐通道离散度诊断，看它的活跃集中在哪个（非 Light）通道？**诊断已就绪、可一条命令跑出并自动判读**
   （在当前变换后 m1-out 上，无需重放）：
   ```bash
   # 产出变换后逐通道离散度（探针网格取单点，快）
   bash deploy/scripts/syn-m2-probe.sh --r-grid 1.0 --k-grid 10 \
       --out-name m2_probe_tmp.csv --dispersion-name m2_dispersion_logtf.csv --max-messages 2000000
   # 自动判读 G 落在哪个（非 Light）通道
   python3 deploy/scripts/m2_dispersion_report.py --csv docs/m2_dispersion_logtf.csv --target G
   ```
   （判读器已用变换前数据验证：能正确指认 C/D 的 Light 通道。）
3. **确认即写入**：八台机选值（A/B/E/F/H=0.75、C=1.0、D=0.75、G=1.75）经设计会话确认后一次性写入
   `SYN_M2_R_PER_DEVICE`，M2 收口。
