## 二、由我选定的写法（请设计会话确认）

1. **冷启动的训练版本。** 决定十三把训练版本定义为训练完成时的参数版本。训练期间到达的轮进缓冲、不被处理，所以上下文模块在训练完成时所知的版本，就是提交训练那一刻的当前版本。我据此规定：收集期的窗口一律存原始值，提交训练时按当时的当前版本统一标准化，并把这个版本记入状态；从检查点恢复后重新提交，沿用同一版本。第一批的做法是每一轮按它到达时的版本标准化，收集期内发生零级时训练集里混着两个版本。命令回路关闭或收集期内没有零级时，两种做法逐位相同。
   - **需要注意的后果：**链式实验乙档中，E 的第一条零级在 03-16 生效，落在上下文模块的收集期（03-08 至 03-24）之内，所以在线时 E 的冷启动训练版本是二或三，而不是开放问题第十二条实验所用的版本一。
2. **一级切换的时刻按事件时间定义。** 交接文档要求「旧模型继续服务直至新模型标定完成，原子切换」，同时要求短重放两次运行逐位相同。如果按处理时间，在训练结果收回后的下一个窗口边界切换，切换点取决于训练用了多少墙钟时间，两次运行不可能逐位相同。我采用补遗四冷启动已经验证过的机制：
   - 旧模型服务到提交重训的那一轮为止；
   - 此后到达的轮进缓冲，输出水位线保持；
   - 新模型标定完成后，由它从缓冲头开始评分。
   这样，事件时间上的「标定完成」就是提交时刻，旧模型确实服务到这一刻为止；单元测试验证了训练快慢不影响输出。具体到两侧：
   - **生效前侧：**提交发生在生效后第一条入口轮。生效时刻所在的那个窗口跨过切换：未满的部分按新版本从原始值重新标准化，由新模型评分。
   - **生效后侧：**旧模型继续服务 N 天，跨过生效后第 N 天的那个窗口收满之后提交。
3. **一级训练集的来源与对齐。** 上下文模块保留在线窗口的原始值历史，长度为 N 加一到二天；待做的一级范围内的窗口不淘汰。训练集取末轮落在范围内的窗口，窗口边界沿用上下文模块自己的在线窗口。离线实验的窗口是从范围起点起划分的，两者的窗口边界可能错开几轮。历史从该台进入在线态时开始积累，所以冷启动后不足 N 天就收到一级时，训练集会短于 N 天，日志会记下实际窗口数。
4. **N 天按秒计。** 范围取生效时刻前后 N 乘 86,400 秒（单元测试按「每天轮数乘十秒」缩短），不按当地日计；跨过夏令时切换的那一天因此差一小时。
5. **模型代数。** 一级与二级都不改变参数版本号；没有中间零级的一级，训练版本也与原来相同。所以性能层无法靠版本号判断模型是否换过。我在评分记录上新增模型代数（一级切换与二级完成各加一，此前为空），性能层按它清空。
6. **冲突与失败的处理。**
   - 一级只在在线态接受，已有待做的一级时忽略新的一级；
   - 二级在训练进行中忽略；
   - 一级重训失败两次时放弃，旧模型继续服务；
   - 数据接入模块里，前一条一级或二级尚未转发时，新的一条替换它。
   以上情况都写一条以 REPORT 标明的日志。
7. **影子超阈率的统计口径。** 影子评分逐窗写在监测快照上，每台每小时的影子超阈率由离线工具从快照汇总，算子内不做小时累积。影子评分要求同时打开上下文通道的监测侧输出。

## 四、决策矩阵升级格（决定十六）动手前需要确认的问题

1. **重训完成的时刻。**冷却期为「该台重训完成后七天」，聚合模块却看不到上下文模块何时完成。按第二节第 2 条的事件时间口径，重训完成就是生效时刻（生效前侧）或生效后第 N 天（生效后侧），聚合模块可以由命令自己算出。请确认采用这一口径。
2. **K_up 内「再次」的含义。**「一级之后 K_up 天内性能层再次确认」与「零级之后 K_up 天内同一通道再次持续」，是从生效时刻起算，还是从重训完成时刻起算？「再次」是否要求中间先出现一次撤销或回落？
3. **级别之间的冷却。**零级的冷却期（生效后一个当地日）是否同样阻止一级与二级的决定？一级与二级的冷却期是否阻止零级？
4. **「两层同报」的判定。**沿用现有「同一天性能层持续且该通道数据层同日偏离」的写法（命令依据里已有「两层同日同报」），还是另有定义？
