# 适应执行第二批开工核对与第一项验收（2026-11-09）

依据：交接文档 `docs/handover/handover_m6_batch2_zh.md`（开发设计日志 1.35 版）。本报告对应交接文档第十节要求的「开工核对」，并附第一项（聚合模块按版本过滤）的验收结果，即 V-M6b-1（版本过滤的单元测试、开环重跑与二十三种配置逐条相同）。

## 一、对交接文档的理解与执行顺序

- 第一项是聚合模块按参数版本过滤日结论（决定十四），已在开发机完成，验收结果见第三节。
- 第二项链式离线实验（决定十五）需要八台设备的轮表。用户在 Mac 上为八台各提取一次原始轮表；设备 E 的十四段注入由开发机在读入轮表时按在线注入器的规则施加，并重算守卫标志，所以用户不需要为注入单独提取。
- 第三项是开放问题第十二条的离线实验（一级重训的长度 N 与热冷启动），在链式离线实验之后、在线实现之前进行。
- 第四项是一级、二级与决策矩阵升级格的在线实现和短重放；第五项是全量重放。两项都使用设计会话按链式实验判据选定的重估窗口。

## 二、实现时选定的写法（交设计会话确认）

交接文档第三节写明「只引用与该台当前版本相同的日结论」与「段在版本变化时随数据层状态清零而结束」。下面五条是交接文档没有写死、实现时选定的写法。这些写法在开环输入上都不起作用，开环结果与收口逐条相同。

1. **当前版本的取法**：某台设备的当前版本，取它最近一个有读数的告警节拍内各轮版本号的最大值；决策节拍沿用这个值。命令回路关闭时版本号为空，一律按版本一处理。
2. **过滤的范围**：与当前版本不同的日结论一律视为不存在。这既包括偏离标志与状态转移，也包括「该日可判」，所以在场设备的计数和数据层通道的回落判定都只看同一版本的日结论。
3. **段结束的时刻**：版本变化在第一个出现新版本的告警节拍上生效。该台数据层通道的「同一段偏离」与漂移状态在这个节拍上结束，不等到下一个决策节拍。性能层的段不受影响，因为性能层的版本是训练版本，与零级无关。
4. **不做过滤的两项**：离群率爆发不是日结论，所以不按版本过滤。日界复核中的「当日不可判」报告的是当日自己的日记录，也不过滤。
5. **现场条件的参照宽度与钟点基线**：这两项仍取首次冻结时的参照（P10、P90）和冻结后十天的钟点基线，换版本后不更新。交接文档写明小时均值不随零级变化，但没有提到参照宽度。如果设计会话认为换版本后应改用新参照的宽度，需要另行裁决；这一条不阻塞链式实验。

## 三、第一项验收结果（V-M6b-1）

| 核对项 | 结果 |
| --- | --- |
| 单元测试 | 新增两个用例，均已通过。`FleetDecisionFunctionTest.versionFiltering` 验证三件事：跨版本的前一日不构成「连续两日偏离」；段在版本变化时结束，新版本上的持续偏离作为新的一段再发一条命令，段内序号从一开始；换版本当日的小时不再带旧版本的数据层标志与漂移标签。`M7InputAssemblerTest.versionMapping` 验证轮、日记录与数据层转移都把版本号带进输入，版本号为空时按一处理。全部 177 个测试通过。 |
| 开环默认配置重跑 | Python 参考实现与 Java 离线运行器的告警（8,391 条）、命令（76 条）、复核（48 条）三份日志，都与 `docs/m7/run`（聚合模块收口基线）逐字节相同。 |
| 二十三种配置的 Java 与 Python 核对 | `m7/equality_configs.py` 重做，二十三种配置全部逐条相同，`docs/m7/equality.md` 与收口时逐字节相同。 |
| 版本分支的 Java 与 Python 核对 | 开环输入走不到版本过滤的分支，所以新增 `m7/version_equality.py`。它在收口输入上合成六次换版本（B、C 各一次，E、G 各两次），用五种配置分别运行两边，三份日志全部逐条相同，结果表见 `docs/m7/version_equality.md`。合成的换版本使告警从 8,391 条变为 8,259 条、命令从 76 条变为 77 条，说明分支确实被执行到。 |

**改动范围**：`FleetDecisionFunction`（日结论带版本号、按版本过滤、版本变化时结束数据层通道的段）、`M7Input`（版本号字段）、`M7InputAssembler`（把版本号记进节拍观测与日结论）、`M7OfflineRunner`（读可选的 version 列）、`m7/decide.py`（同步实现，选定写法记为文件头第 f 条）。

第二项需要八台设备的轮表，由用户在本地 Mac 上运行 `eda/m6a_extract.py` 提取。具体命令与期望产出写在回复正文里。轮表推送之后，开发机开始链式离线实验。

## 五、交设计会话的事项

第二节的五条写法请设计会话确认。这些写法不阻塞第二项链式离线实验，可以与用户的提取并行进行：如果设计会话改动其中某一条，开发机按新口径重跑链式实验即可，不需要重新提取轮表。

## 复现方式

- **执行环境**：开发机或本地 Mac，仓库根目录，JDK 11，python3.9 及以上。
- **调用命令**：
  ```bash
  mvn package -DskipTests
  python3 m7/decide.py --out-dir /tmp/m7py                 # 与 docs/m7/run 逐字节比较
  java -cp target/iot-anomaly-detection-1.0-SNAPSHOT.jar com.leejean.m7.M7OfflineRunner --out-dir /tmp/m7java
  python3 m7/equality_configs.py --cp target/iot-anomaly-detection-1.0-SNAPSHOT.jar
  python3 m7/version_equality.py --cp target/iot-anomaly-detection-1.0-SNAPSHOT.jar
  mvn test -Dtest='FleetDecisionFunctionTest,M7InputAssemblerTest'
  ```
- **前置条件**：`docs/m7/inputs` 已由 `m7/prepare_inputs.py` 生成。
- **期望产出**：两份重跑的三份日志与 `docs/m7/run` 逐字节相同；两个核对脚本的退出码都是零；测试全部通过。
- **常见失败**：如果 Maven 报 JDK 版本不在 [11,12)，说明需要设置 `JAVA_HOME` 指向 JDK 11。
