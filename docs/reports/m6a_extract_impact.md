# 两处提取缺陷对已收口阶段的影响（1.30 版裁决第五项，2026-11-05）

依据：缺陷的事实与成因见 `docs/reports/m6a_extract_check.md`。

**做法**：
- 修正后的 `eda/m5a_extract.py` 与 `eda/m7_extract.py` 由用户另行输出到 `docs/m5a/extract_fix/` 与 `docs/m7/extract_fix/`，已收口的基线没有被覆盖。
- 在临时目录里用原提取与修正后的提取各跑一遍下游：数据层离线实验 `m5a/run_offline.py`；聚合模块的输入准备 `m7/prepare_inputs.py`、默认配置决策 `m7/decide.py`、离线报告表 `m7/report_tables.py`（11 种配置）、时间参数扫描 `m7/scan_time_params.py`（12 种组合）、时延表 `m7/latency_table.py`。
- **对比基准的有效性**：用原提取重跑的全部输出与已收口的文件逐字节相同（报告只差生成时间与路径），所以下表的差别只来自两处缺陷。

## 四、归类（供设计会话按裁决判断）

**属于已进入阶段报告的计数**：
- 离群率爆发次数（245 / 247 变为 248 / 250），见数据层阶段报告与待决事项文档。
- 由它引出的两项对照计数（106 变为 109，90 变为 93）。
- 「零确认」的结论本身不变。

**属于中间量或末位数值的**：
- 长记忆三张表的数值（类别与日期都不变）。
- 质量比例与参照宽度的末位。
- 聚合模块的一个告警字段与一处表格数值（+2.72 变为 +2.71）。
- 开工核对用的单精度统计。

**不受影响的**：长记忆的全部状态转移与偏离日数，聚合模块的全部命令与复核、时间参数扫描与时延表，以及全部 Java 在线与离线之间的等值结论。

是否重跑并更正已收口文件，请设计会话按 1.30 版裁决第五项的判据决定。重跑的命令就是上面所列各脚本按默认目录运行；修正后的提取已经在库，不需要用户再运行任何脚本。
