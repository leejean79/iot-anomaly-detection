# 聚合决策四个时间参数取非默认值时的可执行定义：需要设计会话补写的三点（2026-10-29）

依据：交接文档 1.23 版第四点四与第七节判读口径第 9 条。默认取值（告警节拍一小时、决策节拍一个当地日、等待时长一个日界、生效提前量
一天）已经实现，Java 与 Python 逐条相同。生效提前量 Δ 的一般形式没有歧义，已经参数化：生效 = 决定时刻 + Δ，冷却期截止 = 生效之后
一个当地日；Δ 取一小时与默认值时，Java 与 Python 也逐条相同。另外三个参数取非默认值时，交接文档给出了范围，但没有给出可以照着写
代码的定义，下面三点请设计会话补写。补写之前，判读口径第 9 条只做 Δ 一维的扫描。

## 一、等待时长 W 小于一天时，「只用性能层与小时标志判持续」指什么

- **事实**：数据层按日给结论，所以 W 小于一天时，持续判据只能来自性能层与小时节拍的标志。小时节拍的五个标志里，按小时变化的只有
  点通道、上下文通道与性能层三个。如果点通道或上下文通道的标志连续 W 小时也算持续，那么检测通道单独就能触发零级命令，这与决策
  矩阵「只有检测通道告警、无漂移事件，不发命令」的两行相矛盾。
- **做法甲（推荐）**：W 小于一天时只看性能层：一段「已确认未回落」从开始起持续满 W 仍未回落即为持续。数据层的两条规则仍按日界判定。
- **做法乙**：再加上「点通道或上下文通道标志在连续 W 小时内每小时都有」，并在决策矩阵里补一行，写明它的归因与响应。
- **需要知道的事实**：全量数据上，性能层的确认几乎都在一天之内按回落规则结束（默认配置下没有一条命令只由性能层触发），所以按做法
  甲，W 取六小时或十二小时会得到多少命令，要跑过才知道。

## 二、决策节拍 τ_cmd 短于一天时，各条规则在哪些节拍上判定

- **建议的写法**：决策节拍在每个 τ_cmd 边界触发（从当地零点起算）。数据层的两条规则（连续两日偏离、当日偏离且性能层同日已确认）只在
  当地日界那一个节拍上判定，因为数据层的结论每天只更新一次；性能层的规则在每个节拍上判定。冷却期与「同一段偏离只发一次」照旧。
- 请设计会话确认，或给出另一种写法。

## 三、告警节拍 τ_alert 取十分钟时，五个标志与现场条件怎样定义

- **建议的写法**：点通道离群率按十分钟计，门槛 p_point 按十分钟的离群率重新推导；上下文通道标志即该十分钟窗口超阈；性能层标志不变；
  数据层标志仍引用前两个日界；爆发标志仍取「前两个小时之内」报警、已经发出的爆发；现场条件仍按当地钟点（整点小时）累计，十分钟节拍
  只是把同一钟点的判定做六次。
- 离线输入目前是按小时整理的，按十分钟在全量数据上运行需要在 Mac 上再提取一次；交接文档对 τ_alert 只要求单元测试，所以建议这一项
  只在单元测试与在线算子中检验。
