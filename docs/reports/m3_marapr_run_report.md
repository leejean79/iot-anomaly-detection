断言一至六全部 PASS；**断言七 FAIL**，八台都显示「无输出」。原因：点通道窗口函数 `PmcodFunction` 把窗口的键
当作设备号使用，键是代理键（如 `F#3`），于是

- 评分与监测记录的设备号变成了代理键，断言七按原设备号对不上；
- 逐设备半径按设备号查找，D（0.75）、G（1.5）查不到而退回全局半径 1.0（G 的离群记录多达 13,932 条即由此而来）；
- 送往上下文通道的标注轮也带代理键，依设备号生效的处理（如 G 的光照通道置零）失效。

已修复（提交 `edd015e`）：窗口函数先经 `DeviceKeys.deviceOf` 还原设备号。新增回归测试：同一输入按代理键与按原
设备号分组，三类输出逐条相同，且逐设备半径确实生效；撤掉修复时该测试失败。这一缺陷是代码开发代理在引入代理键
时遗漏的（只排查了 `getCurrentKey()`，漏了窗口函数的键参数）。由于修复改变了两个通道的输出，按「通过后再提交
长运行」，须重做一次预验证。
