# 聚合模块决策部分（M7）实现前的五点说明（2026-10-29）

依据：裁决书 `ruling_m7_offline_protocol_zh.md` 与交接文档 1.22 版。代码开发 agent 按裁决动手实现时，对照了现有在线算子能拿到的数据，
发现第一点在线上做不到原文的写法，需要设计会话选择；第二至四点是代码开发 agent 选定的可执行写法，报告备案；第五点是涉及适应执行
模块的一项事实。第一点不阻塞其余实现，裁定前先按建议的做法写，裁定后若选另一种，只改一处比较。

## 一、「同步变化」在标准化域比较，在线算子拿不到标准化的分母（须裁定）

- **事实**：裁决第三点要求「标准化小时均值减同钟点基线，超过参照直方图 P90 减 P10 宽度的二分之一（标准化域）」。参照直方图的 P10、P90
  是变换域（光照为 log1p）的值；换到标准化域要除以标准化算子冻结的分母（四分位距，或旁路时为一）。在线算子收到的标准化轮只带标准化
  之后的值与原始值，参照直方图只带 P10、中位数、P90，**没有任何地方带有这个分母**。
- **做法甲（推荐）**：在变换域上做同一个比较：「该通道变换域小时均值减同钟点变换域基线，超过参照直方图 P90 减 P10 宽度的二分之一」。
  标准化是正系数的仿射变换，两边同除以分母即得原文的不等式，所以两种写法在数学上等价（只在最后一位的舍入上可能不同）。在线算子从
  标准化轮的原始值自己做变换，不需要分母，不改上游；离线与在线用同一写法，逐位相同不受影响。零级换版本后照裁决重新累积十天基线。
- **做法乙**：由标准化算子把冻结（及每次零级重估）的中位数与分母附在带参照直方图的那条轮上下发。适应执行第一批本来就在这条轮上加
  附件，但这是对数据接入模块的又一处改动。

## 二、日内基线与小时均值的可执行写法（备案）

- 小时均值 = 该小时内冻结之后、该通道有读数（光照删失不计）的轮的变换域值之和除以读数数；没有读数的小时不做「同步变化」判断。
- 基线 = 从冻结所在的当地日起连续十个当地日（含冻结日冻结之后的部分）里，每个当地钟点的变换域值之和除以读数数（按轮合并，而不是对
  小时均值再取平均）；第十个当地日结束时冻结。全量数据上八台都在 03-08 冻结，基线期即 03-08 至 03-17，与 p_point 的推导期一致。
- 离线输入由提取脚本按小时给出变换域的和与读数数（新增列，需在 Mac 上重跑一次提取）；Python 参考实现与 Java 离线运行器读同一份
  文件、用同一种算术，所以逐位相同。

## 三、两档节拍触发的时刻（备案）

- 小时节拍在 h 终点之后一个滑动步（60 秒）触发：小时内最后一分钟的轮，其到达滑动步的离群判定在 h 终点之后 60 秒才出窗。爆发只取
  发出时刻不晚于 h 终点的（与裁决第一点一致）。
- 日节拍在日界之后同样 60 秒触发，排在该日最后一个小时节拍之后；日界复核紧随日节拍。

## 四、短重放上的现场条件（事实）

短重放从 03-24 开始，各台在 03-25 冻结，十天基线要到 04-03 才冻结，超出短重放区间（03-31）。所以短重放全程处于「基线累积中」，
不会出现现场条件归因；在线与离线在这一点上照样逐条相同，但这条规则在短重放上实际没有被检验，只能靠单元测试与全量离线实验。

## 五、适应执行模块：光照的重估牵涉超越函数（事实）

适应执行第一批的验收要求「Java 重估函数与 Python 逐位相同（没有超越函数，不设容差）」。光照在 log1p 域重估，log1p 正是 1.11 版登记的
跨语言差一位的函数，所以光照通道的重估中位数与四分位距在 Java 与 Python 之间可能差一个最低有效位；其余四个通道没有超越函数，可以
逐位相同。建议光照这一项按 1.11 版的跨语言例外处理（容差 1e-12），其余照原文。
