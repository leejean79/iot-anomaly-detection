## 一、实现与写法（请设计会话确认）

1. **开关的含义。**零级照常用七天窗口重估五个通道。重估之后，集合内的通道（默认为湿度与气压）把中位数、分母、旁路标志与替代标记换回冻结参数，参照直方图也换回冻结时的参照。回填按换回后的参数标准化。集合为空时，函数与原来逐位相同（单元测试 `keptChannelsKeepTheFreezeParametersAndReference` 覆盖了两种情况）。
2. **在线作业。**新增作业参数 `--adapt-keep-channels`，默认取 `Humidity,Pressure`，取 `none` 即回到全部重估。标准化算子在冻结后第一条轮上保存冻结参数与冻结参照，供每次零级换回。
3. **作业的重估窗口默认值。**作业参数 `--adapt-reestimate-days` 的默认值原来是一天，现按链式实验裁决第一项（选定乙档，七天窗口作为默认）改为七天。
4. **数据层在换版本时的行为没有改动。**数据层收到新版本的参照时，五个通道的偏离状态一律清零、从该轮所在当地日重新开始。湿度与气压的参照虽然没有变，状态同样清零。这沿用第一批的定义，裁决第一节没有要求改动。

- 第二项的「明显」，裁决没有给数值。我在运行前写定为「不超过 284 的一半，即 142」。235 介于 142 与 284 之间，所以记为「有所降低但未达明显」。
- 两档的六十条命令逐条相同，包括设备、命令日与触发通道。加开关一档中，没有一条命令的触发通道只有湿度或气压。

## 四、第二项未达「明显」的数据事实（按 CLAUDE.md 第八节，时间为布里斯托当地日）

以下只报事实，不判定成因。

1. **加开关之后，湿度与气压的偏离日数与开环对照完全相同。**在加开关一档 60 条命令各自的七天窗口里，非触发的湿度偏离日为 68，气压偏离日为 167，与开环对照在同样窗口里的数字逐一相同。原乙档的同样窗口中，湿度为 131，气压为 153。所以开关把湿度的连带偏离降回开环水平，减少 63 日；气压反而增加 14 日，也回到开环水平。
2. **气压的偏离是相对冻结周的、八台同日发生的偏离。**全程气压偏离的设备日数，开环、原乙档、加开关三档都是 185。加开关一档中，八台各自可评价日的约一半气压偏离（每台 21 至 24 日），而且集中在相同的 24 个当地日上：03-09 至 03-13、03-19、03-24 至 03-27、03-29 至 03-30、04-05 至 04-08、04-11 至 04-12、04-21 至 04-24、04-28 至 04-29。大多数日子八台全部偏离。
3. **冻结周与偏离日的气压。**八台的冻结时刻都在 03-08 当地零时前后，冻结周为 03-01 至 03-07。以 E 为例，冻结周的气压日中位数为 100,744 至 102,373 帕，按冻结尺度 900 帕计为 −1.17 至 +0.64 个尺度。偏离日中，03-09 至 03-13 为 −1.06 至 −2.52，03-24 至 03-27 为 +0.72 至 +0.99，04-06 至 04-08 为 −2.55 至 −3.61，04-23 为 −2.17（数值见 `docs/reports/m6b_q12_supp_report.md` 第三节第 1 条的当地日剖面）。
4. **出处材料。**本项目的数据出自 Erol 等人的论文，八个端点装在同一实验室的不同位置。气压随天气变化，八台同日偏离与这一安装条件相合。这只是并列陈述，成因由设计会话判定。

## 五、需要设计会话判断的事项

1. **第二项预期未达「明显」。**加开关之后，剩余的 235 日中有 167 日是气压相对冻结周的偏离，与开环对照相同。开关能消除的是零级重估带来的那一部分；这部分在湿度上明显，在气压上没有。是否把这一结果登记为数据事实，并据此确认开关作为新的闭环基线，请设计会话裁决。我没有改动预期、判据或开关的定义。
2. **跨主机的末位差别（如实登记）。**原乙档与开环对照重跑时，数据层日记录各有一个值与已提交的结果不同：都是数量级约 1e-322 的显著性值，只在最后一位有差别，偏离判定不受影响。显著性的计算调用 `Math.exp`；Java 规范允许它与精确结果差一个末位单位，并可随处理器而不同。在本机上，`Math.exp` 与严格版本 `StrictMath.exp` 在约十分之一的参数上不相同。已提交的结果生成于 11 月 9 日；此后开发机至少重启过一次，当前的内核版本也与当时不同。今天在同一主机上运行两次，结果逐字节相同。所以「逐位相同」这一类验收，在同一台主机上成立，跨主机时这类末位差别可能出现。如果短重放与全量重放需要跨主机比较，是否改用 `StrictMath.exp`，请设计会话一并裁决。改用后，已提交的结果需要重新生成。

## 六、复现方式

- **执行环境**：开发机或本地 Mac，仓库根目录，JDK 11，python3.9 及以上。
- **调用命令**：
  ```bash
  mvn package -DskipTests
  java -Xmx6g -cp target/iot-anomaly-detection-1.0-SNAPSHOT.jar com.leejean.m6.ChainDriver \
       --variant D7 --keep-channels Humidity,Pressure --out-dir docs/m6b/chain/D7K
  python3 m6b/chain_check.py --variants D7K --out docs/m6b/chain/check_D7K.md
  python3 m6b/chain_keep_report.py
  python3 m6b/chain_report.py --variants open,D7,D7K --out docs/m6b/chain/report_tables_D7K.md
  ```
- **前置条件**：八台轮表在 `docs/m6a/extract/`，E 的注入轮表在 `docs/m6b/extract/`，`docs/m7/inputs` 已生成，原乙档的输出在 `docs/m6b/chain/D7/`。
- **期望产出**：驱动约二十五秒；`chain_check.py` 退出码为零；三份表格与本报告的数字一致。
- **常见失败**：Java 内存不足时加大 `-Xmx`；缺少 `rounds_E_inj.csv.gz` 时，按原链式报告第九节的命令重新生成。
