# 适应执行第一批轮表的核对：两处提取缺陷（2026-11-05）

依据：`eda/m6a_extract.py` 第一版生成的轮表（提交 `3cd9849`）；排查按 CLAUDE.md 第八节的顺序进行，两处都停在第一层（代码），属于实现缺陷，不是数据事实。

## 一、零级重估的跨语言比较已经通过

在第一版轮表上做了六组比较：G（03-25 日界）与 B（03-16 日界）各取重估窗口一天、三天、七天，比较 Python 参考实现 `m6a/reestimate.py` 与 Java 离线运行器 `M6aOfflineRunner` 的输出。

结果：四个非光照通道逐位相同，光照通道最大差 8.9e-16（容差 1e-12）；每组比较 4,757 至 5,689 个值。

这一结论只说明两边的实现相同，与下面两处缺陷无关：两边读的是同一份轮表。轮表修正之后会重做一遍。

## 二、缺陷一：pandas 默认解析器把 17 位有效数字的读数解析差最后一位

**现象**：轮表复现的冻结参照中，G 温度的 P10 是 20.434999465942386，而 `docs/m5a/extract/refs.csv` 与 `docs/m7/inputs/refs.csv` 里是 20.434999465942383。

**原因**：
- 原始数据里大量温度、湿度、气体读数写成 17 位有效数字，例如 `20.434999465942386`。
- pandas 默认的 C 解析器（`read_csv` 与 `to_numeric` 都是）不保证正确舍入，会把这类文本解析成相邻的双精度数 20.434999465942383。
- 在线的 `Double.parseDouble` 与 Python 的 `float` 都是正确舍入，得到 20.434999465942386。
- 用 `float_precision="round_trip"` 的 pandas 也得到 386。

**范围**（按 B、G 两台的全部读数统计）：

| 通道 | B 解析差一位的读数 | G 解析差一位的读数 |
| --- | --- | --- |
| 温度 | 40,090 / 494,546 | 41,907 / 519,288 |
| 湿度 | 32,532 / 494,546 | 33,145 / 519,288 |
| 气体 | 4,855 / 494,546 | 9,162 / 519,288 |
| 气压、光照 | 0 | 0 |

**处理**：轮表按原始文本逐个用 `float` 解析，与在线相同。早先用 pandas 默认解析的 `eda/m5a_extract.py` 与 `eda/m7_extract.py` 都有这一缺陷，见第四节。

**顺带的更正**：`docs/m7/extract/meta.md` 里「单精度不能精确表示」的条数是在 pandas 解析值上、带两倍间距容差算出的，气体记为零。按正确解析并逐位判断，三个通道都有大量读数不能被单精度精确表示：

| 通道 | B | G |
| --- | --- | --- |
| 温度 | 181,158 | 177,019 |
| 湿度 | 139,907 | 141,374 |
| 气体 | 23,054 | 38,681 |

缓存用双精度的结论（1.29 版裁决第六项）不变，而且依据更充分。

## 三、缺陷二：漏掉了没有检测通道读数的轮

**现象**：
- 用轮表、经模拟器重演点通道，逐小时离群轮数与全量在线运行（`docs/m3_a4/full_fix/scores.jsonl`）对照：共同的 1,288 个小时里，入口轮数全部相同，离群轮数只有 G 冻结后的第一个小时（03-08 00 时，世界协调时）不同，在线 6 条，模拟 10 条。
- 在线的第一个点是 00:28:10 那一轮，而按轮表计数，这一轮是第 60,480 轮，本应属于预热期。也就是说，在线比轮表早冻结一轮。
- 另外，短重放的在线日记录（`docs/m5a/verify`）中，G 在 03-29 与 03-30 两天的轮数各比轮表多一轮。

**原因**：
- 在线的成轮器（`RoundAssembler`）对同一设备任何一条可解析的读数都建轮，包括质量通道（MIC、RSSI、Accelerometer）与未知传感器。所以只有这类读数的时间戳，是一条五个检测通道全部缺失的轮。
- 这类轮不进点通道，也不进重估样本，但计入冻结所数的轮数与数据层的逐日轮数。
- 提取脚本只看五个检测通道，漏掉了它们。

**处理**：`eda/m6a_extract.py` 已修正：任何可解析读数的时间戳都成轮；畸形读数不成轮，与在线解析器相同。合成数据上已检验，质量通道、未知传感器各成一轮，畸形值不成轮。需要用户重新运行一次提取。

**重新提取后的核对项**：
- G 冻结后第一个小时的离群轮数应为 6 条。
- 短重放区间（03-24 至 03-31）B、G 的逐日轮数应与在线日记录相同。

## 四、交设计会话的事项

两处缺陷同样存在于已收口阶段的提取脚本 `eda/m5a_extract.py`（数据层离线实验）与 `eda/m7_extract.py`（聚合模块离线输入）。

- **影响的性质**：
  - 缺陷一使约 8% 的温度、湿度读数差最后一位，对分布统计量的影响在最后一位的量级。
  - 缺陷二使少数设备的冻结晚一轮，并使个别日的轮数少一。
- **不受影响的结论**：
  - 已收口的等值结论里，凡是 Java 在线与 Java 离线之间的比较（例如 V-M7-3 短重放等值），都不受影响，因为两边都不经过这两个脚本。
  - 聚合模块 Java 离线运行器与 Python 参考实现之间的比较，两边读同一份输入，也不受影响。
- **可能受影响的结论**：以这两个脚本的输出为数据、与在线结果直接对比的地方，可能出现最后一位的差别或个别日轮数差一。

是否修正这两个脚本并重跑相应的离线输入，请设计会话决定。修正本身是机械的，即本轮对 `eda/m6a_extract.py` 所做的两处改动；重跑需要用户在 Mac 上运行。
