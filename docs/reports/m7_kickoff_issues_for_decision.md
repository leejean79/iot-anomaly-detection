# 聚合模块决策部分（M7）开工核对：需要设计会话裁定的事项（2026-10-28）

依据：交接文档 `docs/handover/handover_m7_decision_stage_zh.md`（开发设计日志 1.19 版）。代码开发 agent 在动手之前，逐条对照了现有代码、
三次逐位相同全量运行的转储（`docs/m3_inject`、`docs/m3_a4/full`、`docs/m3_a4/full_fix`）与前两个阶段的离线产出。下列事项或与交接
文档的写法不符，或交接文档没有写定。每条给出事实、影响与建议做法，由设计会话裁定。第一至四节会改变实现或实验的含义，须在动手前
裁定；第五至十节是可执行定义的补全，给出了建议的默认写法；第十一节是缺失的材料。

## 一、全量转储里没有漂移主题，两层监测的输入须由离线产出拼装

- **事实**：三次全量运行都在性能层与数据层上线之前完成，提交时没有打开这两层。转储里只有点通道离群记录（`scores.jsonl`，
  72,677 条，含之后滑动步的重复）与上下文通道主分（`m3_scores.jsonl`），没有漂移主题；m1-out 与监测主题也不在仓库里（监测转储当时
  只留在 master 上）。交接文档第三节「漂移主题中层标记为性能层或数据层的事件」在这批转储上不存在。
- **现有的替代**：
  - 性能层：`docs/m5b/grid/events/c0.99_r0.5_10min_k36_with_injection.csv`，由 Java 离线运行器在全量运行的上下文主分上算出，
    已证明与在线逐条相同（V-M5b-3，离线与在线等值）。
  - 数据层：`docs/m5a/lm_transitions.csv`、`bursts.csv` 与 `extract/daily.csv`、`extract/quality.csv` 的「不剔除注入」一遍，由
    Python 离线实现在原始数据上算出，已证明与 Java 逐条相同（V-M5a-1）。
  - 每十分钟的入口轮数：`docs/m5a/extract/denominators.csv`（由原始数据重算）。
- **缺少的**：每台每小时的缺轮比例与守卫打标比例，以及第二节「现场条件」所需的各通道小时均值，现有产出里都没有，须在存有原始数据
  的本地 Mac 上新做一次提取（与 M5a 离线第一步同一做法）。
- **建议**：离线输入按上面拼装，报告写明每路输入的出处；新增一个 Mac 上运行的提取脚本，产出每台每当地小时的轮数、入口轮数、守卫
  打标轮数与五个通道的小时均值。另一个做法是在集群上开一次打开两层监测的全量重放，得到真正的漂移主题转储；代价是一次全量运行
  （约十小时），收益是输入出处统一。建议前者，并在短重放（V-M7-3，短重放等值）中用真实的在线输入核对。

## 二、性能层的「已确认未撤销」没有结束的时刻

- **事实**：性能层的持续性核对（`DriftGate`）中，撤销只针对候选：候选之后的六个元素中位数跌回门限即撤销；一旦确认，核对状态清零，
  之后**没有任何事件**结束这次确认。性能层检测器是单侧的，也看不到回落（交接文档澄清一已指出）。全量注入运行上，八台各有 4 至 9 条
  确认。
- **影响**：按字面，任何一台第一次确认之后，小时节拍的性能层标志永远为「有」，日节拍的第三条「持续」规则（确认跨过日界仍未撤销）
  永远成立；决策矩阵中「只有性能层、日界前撤销、瞬态」这一行永远不会出现。
- **做法甲（推荐）**：由本模块自己定义确认的回落，不改性能层：确认事件里带有核对的参照与门限（`reference`、`threshold`），本模块
  消费同一路上下文主分，确认之后按与核对相同的规则，取最近六个元素的中位数，一旦不高于门限即记为「确认已回落」。
- **做法乙**：确认的有效期取固定时长（例如 W 或一天）。
- **做法丙**：确认只在其发生的当地日有效。

## 三、离线实验中零级命令不被执行，同一段持续偏离会反复发命令

- **事实**：本阶段的命令只发出、不执行（交接文档阶段顺序说明）；离线实验同样不模拟执行。数据层的状态转移是对冻结参照的，参照
  不重新冻结，偏离就不会结束：例如 B 的气体在 03-14 之后 44 个可判日中 38 天偏离。按第四点二，冷却期（一天）过后若仍满足「持续」，
  日节拍会再发一条零级命令；B、D、E、H 的气体在离线实验中大约每两天收到一条命令，持续约六周。
- **还需确认的一点**：零级命令被执行后，数据层的参照是否随之重新冻结。澄清一（回落时数据层看到向下偏离，再以第二次零级映回）
  隐含「重新冻结」，但这属于适应执行模块的定义，该模块的交接文档还没有到（第十一节）。
- **建议**：离线实验按规则原样发命令，同时在命令日志中标出「同一段偏离的第几次命令」，报告分列首次命令与重复命令；判读口径第 2、7、
  8 条按首次命令统计。是否另设「同一段偏离只发一次」的规则，由设计会话决定。

## 四、小时节拍引用了当时还不知道的日结论

- **事实**：数据层的日结论（进入偏离、当日是否可判）在当地日结束时才发出。下面三处在小时 h 引用了 h 所在当地日的日结论：
  - 归因第 1 条「该台当日被数据层标为不可判」；
  - 归因第 3 条「本日界或上一日界有某通道的进入偏离」，其中「本日界」是 h 所在日的结束；
  - 决策矩阵中分布切换一行的「该台点通道告警静默一个窗长」，静默须在告警发出之前决定。
- **影响**：在线算子在整点发告警时不可能知道这些结论；若等到日界再发，告警就晚了最多一天，与「告警需要更快」的决定二相违。
- **建议**：小时告警只用整点时已知的信息：「当日不可判」改为「该小时不可判」（只看小时质量），「本日界或上一日界」改为「上一日界或
  再前一个日界」（即 h 所在日之前的两个日结论）。另在日界时对当日的小时告警做一次「日界复核」，写入命令日志旁的一份复核日志：
  补标当日不可判，把当日爆发小时的「异常」改记为「分布切换」。复核不改已发出的告警。

## 五、点通道门槛 p_point 的推导期在标定周没有数据

- **事实**：点通道在标准化预热期（标定周 03-01 至冻结）不出分，全量转储中第一条离群记录在 03-08 00:20；标定周的小时离群率不存在。
- **建议**：改用已登记的平稳日参照期（03-08 至 03-17，0.72 版裁决）各小时离群率的第 99 百分位，运行前由离线工具推导并写入报告；
  或用已登记的平稳日清单。上下文通道同理，它在 03-24（B、H 在 03-26）才开始出分，交接文档对它只用固定的 p_ctx，不受影响。

## 六、上下文通道与性能层从 03-24 才有输出

- **事实**：上下文通道经过训练、早停与阈值标定之后，第一个主分在 03-24 18:34 至 19:23（B 03-26 15:12，H 03-26 00:03）；性能层
  依赖这些主分，还要再攒 30 个元素。
- **影响**：片段矩阵中 03-14 起的气体抬高与 03-22 起的三月事件的前段，只有点通道与数据层两路信号；「三月事件中性能层确认跨过
  日界」只可能发生在 03-25 之后。这不改规则，但第七节两段的预期应据此读。
- **建议**：报告中逐段注明当时可用的信号路数。

## 七、共模门槛在在场设备很少时的取整

- **事实**：门槛取在场设备数乘四分之三向上取整：在场 1 台时门槛为 1，2 台时为 2，3 台时为 3。只有一台在场时，它自己的任何标志都会
  被判为「全局」，局部的「异常」变成「环境事件」。
- **建议**：全局另设至少两台的下限；或者照规则执行，在报告中单列在场设备少于四台的小时。由设计会话选择。

## 八、现场条件的「连续 K_site 天」与 C 日照直射的预期

- **事实**：第四点二的计数规则是「当日有标志则加一，否则清零」，即要求连续的天数。C 的日照直射段在 04-17、04-20、04-21、04-24、
  04-25，没有三天连续；按字面，计数最多到 2，C 永远不会被归为「现场条件」，与第七节的预期「从第三天起」不符。
- **建议**：明确「第三天」指连续第三天还是累计第三次。若为累计，计数可改为「最近 N 天中出现的天数」（例如最近七天中至少三天）。
  另须写定小时 h 的判定是否包含当日：建议「当日该小时有标志，且此前的计数不少于 K_site − 1」。

## 九、「同步变化」的可执行定义

- **待写定的三点**：
  1. 「同设备另一个通道」指其余四个通道中的任一个，还是排除气压与湿度。建议排除气压与湿度（它们按理论回传第二十一条是天气驱动的）。
  2. 光照在哪个域上比较。建议与数据接入模块和数据层一致，用 log1p 变换域，光照删失值不计入均值。
  3. 「该通道标定周的一个四分位距」的来源。离线可以从原始数据精确算出；在线算子拿不到数据接入模块冻结的四分位距（标准化轮只带
     标准化后的值，参照直方图只带 P10、中位数、P90）。可选做法：
     - 甲，用参照直方图已有的 P10 至 P90 宽度代替四分位距，即「偏离超过参照宽度的某个倍数」；离线与在线同一定义，数据接入模块不改；
     - 乙，本算子在预热期自己收集读数，冻结时算四分位距与各当地小时的均值；八台在预热期约多 19 MB 状态。

     建议甲，倍数由设计会话给定。

## 十、其他需要写定的细节

1. **点通道小时离群率的分母**：建议用该小时的入口轮数（非预热且五通道不缺，与数据层相同），分子只取到达滑动步的判定（与 1.08 版
   一致）。交接文档的「该小时轮数少于标称轮数一半则不可判」与归因第 1 条「缺轮超过质量门槛（百分之二十）即质量问题」两个门槛并存；
   建议都保留：前者只决定点通道标志能否计算，后者决定归因。
2. **参数版本号**：命令里的「该台当前版本号加一」由谁持有。建议本阶段由决策函数自己从零起计，适应执行模块的版本号如何对接，等它的
   交接文档。
3. **生效提前量 Δ 与命令主题**：短重放倍速 120，按第四点四的下限公式，Δ 取一天远大于需要，可用默认。
4. **在线状态**：除交接文档列出的三项外，还需要每台每小时的累加量、性能层每台的确认与回落状态（第二节做法甲）、最近两个日界的数据层
   结论与各台的版本号；体积仍很小，在 V-M7-5（性能）中实测。
5. **短重放区间**：与 V-M5a-3（数据层短重放等值）相同的理由，建议沿用 03-24 至 03-31。
