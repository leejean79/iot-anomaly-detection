- **验收项 V-M6b-2 的两项核对都已通过。** 第一项是驱动程序的正确性：开环对照（命令只发出、不执行）的告警、命令、复核三份日志与聚合模块收口基线逐字节相同，重算的小时离群轮数、数据层日结论与离群率爆发也与收口输入逐条相同。第二项是跨语言等值：三档共 199 条执行的命令，Java 模拟器的新参数、参照直方图与回填附件，与 Python 参考实现在四个非光照通道逐位相同，光照通道的最大差为 8.9e-16，在 1e-12 的容差之内。同一档运行两次，全部输出逐字节相同。

## 一、驱动程序与核对

### 1.1 驱动的构成

- **驱动程序**为 `com.leejean.m6.ChainDriver`，每台设备的逐段推进模拟器为 `com.leejean.m6.ChainDeviceSim`。模拟器调用的都是在线算子用的同一组函数：标准化的冻结与零级、`PmcodFunction` 的滑动步（包括换版本时的清空与回填）、`M5aCore` 的日记录与离群率爆发。
- **每日的推进方式**：八台模拟器先推进到 D 日日界之后一个滑动步。这时 D 日最后一分钟的轮的离群记录都已到达，D 日的日记录也已关闭。驱动把新的日记录、状态转移与爆发交给决策函数，逐小时做告警节拍，再做 D 日的日节拍。新命令按生效时刻（再下一个日界）排进对应设备的模拟器。
- **事件次序与在线相同**：在每一段推进中，先处理轮，再处理窗末不晚于推进时刻的滑动步，最后逐个关闭十分钟（爆发的发出时刻就是关闭时刻），日界定时器到时再关闭当日。命令在生效时刻之后的第一条轮上执行。
- **不随零级变化的输入取自收口输入**：每小时的轮数、入口轮数、守卫轮数、上下文超阈与主分、变换域的小时和，以及性能层的事件，都直接取自收口输入。这是选项一（上下文通道不跟随零级）的直接后果。参照宽度与钟点基线按 1.37 版裁决第五条，取首次冻结时的值。
- **设备 E 的注入**由 `m6a/inject_rounds.py` 施加，用的是收口基线提取时同一套注入与守卫函数。注入后，守卫因为三段卡死注入而打标 1,883 轮，与全量运行中注入之后计算守卫的次序一致。
- **点通道参数**沿用全量运行：k 取 10，窗长一小时，滑动一分钟；半径 D 为 0.75，G 为 1.5，其余各台为 1.0。

## 五、判读口径五：丙型实例

**操作定义。** 交接文档对丙型实例的描述是「命令后回落再命令」，没有给出逐条判别的写法。本报告采用的判别是：同一台、同一触发通道的相邻两条命令，各自命令日的偏移（当日中位数相对参照）符号相反。这表示生效之后，数据层在新参照上看到了反向偏离，并由第二条命令映回。

**计数。** 按这一定义，甲档 43 例、乙档 29 例、丙档 29 例；其中第二条命令在第一条生效后七天内决定的，分别为 27、11、11 例。逐例清单（设备、通道、两条命令的命令日与偏移、反向进入偏离的日期、两条命令的间隔）见 `report_tables.md`。这一操作定义请设计会话确认，见第八节。

## 七、与预期不符之处的排查

按交接文档第十节与 `CLAUDE.md` 第七、八节，排查顺序为代码、交接文档（理论）、数据出处、数据本身。五处不符的共同情况是：开环对照逐条相同，每条命令跨语言逐位相同，同档两次运行逐字节相同，所以代码层没有发现缺陷。下面各条只列排查到的事实，不判定成因。

1. **平稳日命令不少于开环。** 这是排查到数据本身这一层的结果。乙、丙档的 5 条平稳日命令中，A 与 B 在 03-30 的两条，其上一条已执行命令的重估窗口为 03-21 23:00 至 03-28 24:00，覆盖了三月事件。B、G 在 04-17 的两条，其窗口为 04-08 至 04-14，覆盖了四月时段三与时段四的前段。C 在 04-17 的一条，其窗口为 03-28 至 04-03，覆盖了四月时段一。甲档的 10 条中，有 4 条的窗口是事件中的某一天（03-24 或 03-25）。也就是说，新参照建在事件期的数据上，事件过去之后的平稳日相对新参照就成了偏离。平稳日本身的定义来自标定周参照下的 v34 日表。
2. **乙档也有湿度与气压的连带偏离。** 这一条排查到交接文档（理论）这一层。预期写的是「乙、丙档不出现」，测量中乙档以气压为主（每条命令 4 至 6 日）。湿度与气压不是触发通道，参照随零级更新，而气压随天气变化。这一条是否属于数据事实第三十九条候选的范围，需要设计会话判断。
3. **四月共模时段多数归为瞬态事件而非环境事件。** 这一条排查到数据本身这一层，并核对了代码的归因次序。乙档五个时段的 256 个瞬态小时中，202 个带数据层标志（前两日在当前版本上有偏离），54 个只有性能层标志。在聚合模块的六级归因中，瞬态事件排在环境事件之前，有数据层或性能层标志的小时不会再归为环境事件。这一次序沿用聚合模块收口时的定义，没有改动。所以，闭环之后这些时段前两日在新参照上仍有偏离，是这一条的直接原因。
4. **注入小时多数不是异常。** 这一条排查到数据本身这一层。44 个注入小时中，16 个没有告警，原因是那些小时没有检测标志（点通道离群率未超过门槛，上下文通道没有超阈）。另有 10 个归为现场条件，来自第三段温度爬坡的后四个小时与气体爬坡的六个小时；6 个是质量问题，正好是三段卡死注入的六个小时，守卫在这些小时打标。三段尖峰注入只持续 10 至 31 秒，所在小时都没有告警。上下文通道的输入在选项一下与开环相同，所以与开环的差别只来自点通道和数据层。
5. **三月事件中有四台各发了两条命令。** 这一条排查到数据本身这一层。乙档 A、B、H 在 03-24 和 03-27 各发一条，G 在 03-22 和 03-26 各发一条，第二条的触发通道与第一条相同或部分相同。四对中只有 H 的光照一对两次偏移符号相反，计入丙型实例；A、B、G 的两条偏移同号，说明第一条生效之后，事件仍在继续，触发通道在新参照上继续同方向偏离。

## 九、复现方式

- **执行环境**：开发机或本地 Mac，仓库根目录，JDK 11，python3.9 及以上，pandas 与 numpy。
- **调用命令**：
  ```bash
  mvn package -DskipTests
  python3 m6a/inject_rounds.py --rounds docs/m6a/extract/rounds_E.csv.gz --device E --out docs/m6b/extract/rounds_E_inj.csv.gz
  for v in open D1 D7 pos; do
    java -Xmx6g -cp target/iot-anomaly-detection-1.0-SNAPSHOT.jar com.leejean.m6.ChainDriver --variant $v --out-dir docs/m6b/chain/$v
  done
  python3 m6b/chain_check.py          # 每条命令的 Java 与 Python 核对
  python3 m6b/chain_report.py         # 报告表格
  ```
