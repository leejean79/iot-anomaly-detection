## 一、验收项三：短重放等值

**运行设置**：
- 两次配置相同的短重放（a、b），区间 2022-03-24 至 03-31，120 倍速，预热 8,640 轮，设备 E 注入 12 小时温度阶跃（与聚合模块的短重放相同）。
- 命令回路、数据层与上下文通道都打开，作业以 `--restart-attempts 0` 提交，两次运行都没有失败或重启。
- 每次在作业提交之后、重放开始之前，用手工命令工具对 G 写入一条零级命令：生效时刻为 03-28 当地零点（世界协调时 03-27 23:00），决定时刻为 03-27 当地零点，序号一。
- 两次运行中，这条命令都在任何数据到达之前存入状态（到达时水位线为最小值），并由生效时刻之后的第一条轮触发执行。
- 离线一侧用同一份轮表（`docs/m6a/extract/rounds_G.csv.gz`），从短重放的第一轮到最后一轮，由离线模拟器 `M6aSimulator` 与离线运行器 `M6aOfflineRunner` 重演。

## 二、验收项四：性能

| 项目 | 实测 |
| --- | --- |
| 零级执行（重估加回填附件的构造与换参） | 运行 a 为 29.4 毫秒，运行 b 为 23.0 毫秒；重估窗口 8,617 轮，回填 359 轮 |
| 点通道换版本那一个滑动步（清空、回填 359 个点并处理） | 离线模拟器在开发机上实测 2.8 至 3.1 毫秒（三次）；在线没有单独记录这一项 |
| 执行时 G 的缓存 | 34,085 行、1,772,420 字节（冻结前后共约四天的轮） |
| 缓存的满额（深度七天） | 每台约 60,480 行，按每行 52 字节约 3.1 MB；超过深度的行按时间淘汰，不再增长 |
| 标准化算子的检查点（命令回路打开） | 收尾时 24.88 MB（八台），单个子任务最大 3.16 MB |
| 标准化算子的检查点（命令回路关闭，聚合模块短重放中关闭聚合算子的一次） | 收尾时 0.247 MB；预热期蓄水池最大 2.68 MB |
| 整次检查点合计（收尾时） | 命令回路打开 41.43 MB；作为对照，聚合模块短重放中关闭聚合算子的一次为 16.46 MB（那一次还打开了性能层） |
| 检查点耗时 | 179 次全部完成、零失败；端到端中位数 0.158 秒、最大 0.524 秒（对照为 0.122 秒与 0.416 秒） |

**余量**（1.29 版裁决第六项）：
- 单个子任务的标准化算子状态 3.16 MB，是 JobManager 内存检查点单子任务上限 128 MB 的 2.5%。
- 整次检查点 41.43 MB，是检查点通信帧上限 256 MB 的 16%。
- 缓存在七天深度之后不再增长，所以全量重放的检查点体积与本次相当。
