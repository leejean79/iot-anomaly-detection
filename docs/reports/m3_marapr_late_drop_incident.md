## 三、机理（推断）

作业在数据源与事件时间对齐（`AlignEventTime`）两处都设置了 `withIdleness(10 秒)`，原意是让离线设备的分区不拖住
水位线。M3 的训练是同步的：子任务 7 训练 D、G 的约 36 分钟里，D、G 这条路径被阻塞，10 秒后被标为空闲，水位线
改由其余设备推进；这段时间里其余设备读完了到 04-30 的全部数据，水位线随之推到末尾。08:09 子任务 7 解除阻塞，
D、G 积压的轮到达点通道窗口时都已落在水位线之后，允许迟到为 0，于是全部丢弃。

支持这一推断的证据：丢弃只发生在训练最长、串行两台的子任务 7 上；发生在其解除阻塞的同一分钟；丢弃的是
解除阻塞之后到达的那一段（03-25 07:46 以后）。子任务 1（B、C、E）在 08:09 至 08:17 训练 B 时没有丢弃，可能是
那时数据源已经读完，没有设备能再把水位线往前推。

三月重跑的 6,854 轮落在哪些子任务、哪个阶段，还没有查。可以用下面的命令查（只读）：

```bash
bash deploy/scripts/syn-m2-late-drop-history.sh --since 2026-10-01T09:20:00Z --job b6687789 --out-dir docs/m3_march/late_drop
```

2. 三月重跑：有 6,854 轮迟到丢弃，点通道等价性的条件一不成立，「三月重跑与本次点通道逐位相同」不能再由确定性
   保证。三月重跑的缺口核对显示其在线段的缺口与原始数据一致，丢弃可能发生在训练前或训练期间，待上面的查询确认。

   为 0」作为运行结束时的门槛之一。
