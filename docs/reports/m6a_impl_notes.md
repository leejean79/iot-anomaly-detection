# 适应执行第一批（M6a）实现说明：在线部分（2026-11-05）

依据：交接文档 `docs/handover/handover_m6_batch1_zh.md` 1.23 版；开工核对裁决 `docs/handover/ruling_m6a_kickoff_zh.md`；收口记录 `docs/handover/m7_closeout_zh.md` 第五节。

**本次完成的范围**：命令回路的在线部分，即命令进入标准化算子、零级执行、版本号与回填附件下发、点通道与数据层的消费、上下文模块的版本号透传、作业接线、断言八与手工命令工具，以及对应的单元测试。Python 重估移植、离线模拟器与短重放编排尚未开始，见第四节。

## 一、各算子的改动

| 位置 | 改动 |
| --- | --- |
| `m1/RobustScalerFunction` | 把冻结时的计算提成公共的标定函数 `calibrate`，把冻结之后的标准化提成公共函数 `normalize`；冻结与零级共用这两个函数。另加三个只供零级用的入口：取当前参数、写入新参数、写入后让下一条冻结轮带上新参照直方图。命令回路关闭时作业仍直接用这个类，计算次序与改动前相同。 |
| `m1/AdaptiveScalerFunction`（新） | 命令回路打开时代替上一行接在作业里。它按设备键连接命令流，内部包着原来的标准化函数，外加三件事：紧凑缓存、命令状态与定时器、零级执行。零级的计算是一个纯函数 `level0`，离线运行器可以直接调用。 |
| `m6/CompactCache`（新） | 每轮保存五个原始读数（双精度）、时间戳，以及缺失、删失、守卫三组掩码；按时间保留最近七天，每台约 3 MB。检查点由自带的 Kryo 序列化器写出，只写已用的行，只写基本类型。 |
| `m6/AdaptCommand`、`m6/Backfill`（新） | 前者是命令，字段与聚合模块发出的 JSON 相同，原始 JSON 原样保存；后者是回填附件。 |
| `m2/M2Gate`、`m2/PmcodFunction`、`m2/McodCore`、`m2/McodState` | 版本号与回填附件随点下发。滑动步内新到的点版本号变化时，点通道与冷启动在同一处清空状态，再用附件回填。离群记录带版本号。 |
| `m3/M3Function` | 评分记录带上标注轮的版本号；模型与阈值不动。 |
| `m5a/M5aCore` | 收到新参照后替换参照，清空状态转移与当日缓冲，不发回落事件。生效当日已有旧版本的轮时，该日记为「重估日」，不可判。日记录与三类数据层事件带版本号。 |
| 各输出记录 | 版本号都是可空字段，标注为空时不写进 JSON。 |
| `m2/M2Job` | 新增 `--adapt-enabled`（默认关闭）、`--adapt-cache-days`（默认 7）、`--adapt-reestimate-days`（默认 1）；回填窗长取 `--window-sec`。命令源读 `--adapt-topic`，并行度为一，水位线恒为最大值。 |
| `deploy/scripts/syn-adapt-send.sh`（新） | 手工命令工具：按当地日界算生效时刻，按前一日界算决定时刻，向命令主题写一条零级命令。 |
| `deploy/scripts/syn-replay-verify.sh` | 新增断言八（迟到命令为零），加 `--adapt` 时检查。 |

## 二、裁决之外由实现选定的做法（请设计会话确认）

1. **迟到判定比裁决多一个条件。** 裁决第五项按水位线判迟到：命令到达时，生效时刻不晚于数据流的当前水位线即为迟到。实现另把「已经处理过时间戳不早于生效时刻的轮」也判为迟到，原因如下：
   - 上游在定时器里发出一条轮，紧接着推进水位线；命令可能恰好落在这两者之间到达。
   - 这时水位线尚未越过生效时刻，但生效时刻之后的轮已按旧参数标准化，两次运行的结果会因到达先后而不同。
   
   迟到的命令只记日志与计数，不执行。
2. **零级的触发点有两个，二者等价。** 一是生效时刻的事件时间定时器，二是第一条时间戳不早于生效时刻的轮，哪个先到就由哪个触发。两种触发看到的缓存都恰好是生效时刻之前的全部轮，单元测试已检验二者输出逐位相同。
3. **回填附件挂在第一条点通道会接纳的新版本轮上。** 点通道的入口会丢弃有缺失通道的轮。如果第一条新版本轮恰好有缺失，附件挂在它身上就会丢失，所以附件改挂在第一条无缺失的新版本轮上。新参照直方图仍挂在第一条新版本轮上，这与交接文档相同。
4. **点通道回填的范围与判定的屏蔽方式。**
   - 只回填仍在当前窗口内、且早于换版本点的那些点；更早的点已经离开窗口，回填进去也不会再被删除。
   - 离群名单里，轮时间戳早于换版本点的点不再发出，直到它们离开窗口。
   - 点通道的监测快照（离群率、窗口点数）照常统计窗口内的全部点，这一小时内的离群率因此包含回填点。
5. **生效时刻须为滑动步（60 秒）的整数倍。** 如果不是，生效之前、同一滑动步内的轮只会进回填，不会被判定。聚合模块的命令都落在日界上，满足这一条件；手工工具会拒绝不满足的生效时刻。
6. **缓存精度固定为双精度，不设参数。** 提取脚本的统计（`docs/m7/extract/meta.md`）显示，温度有 37,250 条、湿度有 44,576 条读数不能被单精度精确表示，按裁决第四项的判据应当用双精度。单精度会改变重估结果，所以不提供这一选项。
7. **冻结之前到达生效时刻的命令记日志后忽略。** 交接文档没有规定这种情形。
8. **点通道的监测快照不带版本号。** 交接文档列出带版本号的记录是：标准化轮、离群记录、上下文评分、日记录与数据层事件；监测快照不在其中。

## 三、需要上报的一处缺口

聚合模块交接文档（1.25 版）第三节第 4 条要求：引用之前的日结论时，只引用与该台当前参数版本相同的结论，旧版本的结论视为不存在。已收口的聚合模块实现**没有做这一条**：其输入里没有版本号，开环实验与短重放也都没有命令回路，所以至今没有影响。闭环运行（第二批的链式离线实验）需要这一条。

建议在第二批开头补上，补的范围是：聚合模块的输入映射读取日记录的版本号，决策函数按版本过滤；Python 参考实现同步修改。是否现在补，请设计会话决定。

## 四、尚未完成的部分

1. Python 重估函数的移植，以及与 Java 的逐位比较：四个非光照通道逐位相同，光照通道容差 1e-12。
2. 离线模拟器与离线模拟报告（V-M6a-2，六条判读口径）。两个用例是 G 的光照（03-25 日界）与 B 的气体（03-16 日界）。其中的原始数据提取需要用户在 Mac 上运行一次。
3. 短重放编排（V-M6a-3）：03-24 至 03-31，对 G 手工下发一条生效时刻为 03-28 当地日界的命令，并做两次在线运行。
4. 性能测量（V-M6a-4）：缓存的状态大小、检查点体积增量、回填耗时与重估耗时。执行日志里已经记录了重估耗时、总耗时与缓存字节数。

需要说明一点：作业的检查点存放在 JobManager 内存中（单子任务上限 128 MB）。缓存会让每个子任务的检查点增加约 3 MB，短重放时将实测它与通信帧上限的余量。
