## 二、Python 参考实现与跨语言核对（裁决「顺序」第一条）

`m7/decide.py` 补齐了升级格（二级、只有性能层持续、两层同报、零级之后 K_up 天内同一通道新持续段）、各级冷却、模型不在线与重训进行中的抑制、K_fail 保险与按事件起算的冷却和观察窗。模型状态的两种来源与 Java 相同：默认以上下文评分的首条时刻为上线时刻（链式驱动的规则），`--model-events` 时读 `model_events.csv`（在线作业的规则）。Java 离线运行器同样新增 `--model-events`；升级格打开时命令日志多写一列 `cell`（关闭时与收口基线逐字节相同）。

**合成输入**（`m6b/synth_cells.py`）：六台设备，在指定的当地日注入数据层偏离、性能层确认与回落、上下文评分的首条与模型状态事件，使每个格与每种抑制至少命中一次。**核对**（`m6b/cells_check.py`，结果 `docs/m6b/synth_cells/cells_check.md`）：

| 配置 | 输入 | 三份日志 Java 与 Python |
| --- | --- | --- |
| 升级格打开，首条评分为上线 | 合成 | 逐条相同 |
| 升级格打开，模型状态事件 | 合成 | 逐条相同 |
| 同上，K_up 三天、冷却三天、K_fail 五天 | 合成 | 逐条相同 |
| 升级格打开，一级训练窗口在生效之前 | 合成 | 逐条相同 |
| 升级格打开，模型状态事件，决策节拍一小时 | 合成 | 逐条相同 |
| 升级格打开，首条评分为上线 | 收口输入 | 逐条相同（告警 8,391、命令 63、复核 73） |

七个格（含两种改发的零级）与四种复核类别（一级与二级被抑制：模型不在线、一级被抑制：重训进行中、REPORT）全部命中。升级格关闭时，Python 与 Java 在收口输入上照旧逐条相同（告警 8,391、命令 76、复核 48）。

**新链式基线 D7K_up_s 的 Python 对照**：

- 决策层（`m6b/chain_decide_check.py`）：把链式驱动写下的每小时离群轮与参数版本、数据层日记录与爆发并入收口输入，交给 `m7/decide.py`（升级格打开），与链式驱动的三份日志比较到停止命令的决定时刻：告警 1,269、命令 19、复核 28，逐条相同。
- 零级新参数（`m6b/chain_check.py --variants D7K_up_s`）：15 条执行的零级逐条重算，不同 0 条，比较 81,173 个值，光照最大差 8.9e-16。
